# Changelog — Structural Calculation Report Engine

Every version of this engine, newest first. Split out of `CLAUDE.md` §15 in v0.59: the reference document had reached 532 KB, of which this journal was 179 KB, and a reference nobody can read through in one sitting stops being read at all.

**What belongs here, and what belongs in `docs/`.** (Until 2026-10-07 the reference was `CLAUDE.md`; it is now `docs/`, indexed by `docs/README.md`, and the entries below that cite `CLAUDE.md §x` resolve through that index.) This file records *what changed and when*. `docs/` records *how the engine works now* and *why it was built that way* — its §13 keeps the decisions that are settled, its §14 the ones that are not. A rule still in force is stated in `docs/`; how it came to be is here. When the two disagree, `docs/` is the one that is right about today.

Each entry names the sections (§, see `docs/README.md`) it changed, so a rule can be traced back to the version that introduced it.

**Older versions.** v0.100 and every version before it are in [`docs/history/changelog-v0.1-to-v0.100.md`](docs/history/changelog-v0.1-to-v0.100.md), moved there verbatim on 2026-10-10 (issue #31).

- **v0.110** (2026-09-29) — the report's PDF carries the variables the report computes, so reading them back costs nothing (§1, §10quater, §13, §14)

  **The question, and the engineer's answer.** The «Variables» tab of v0.100 lists what `#var`, `#eq`, `#var-unit`, `show-polar-moment` and every `verify-*` compute — values that live in a Typst state and reach **no `data/` file**, which is §1's standing condition on anything computed in Typst. So the only way Python can say what a report holds is to compile it, and a compile is 8-10 s. Three ways to stop paying that were put to him with their prices: **(a)** read on demand, nothing else changes; **(b)** the export writes a JSON, and every *Exporter PDF* goes from ~10 s to ~20 s; **(c)** the PDF carries it, **free**, because the PDF's own compile is the one that pays. He chose **(c)** — «=> c» — knowing the price stated with it: every delivered PDF now embeds a JSON of the report's values.

  **What it is.** `woodcore-document` attaches the whole registry at every compile — `pdf.attach("woodcore-variables.json", bytes(json.encode(var-registry.final())))` in `lib/calc-engine.typ` — and `calc/variables.py` reads it back with the pypdf already pinned. `best()` is the policy in one place: **the attachment where the PDF is newer than every source, a compile otherwise**. Measured on the example project: **0.7 s against 4.4 s**, the same 90 variables in the same 8 domains. ⚠️ **It chooses a price and never an answer** — both routes serialise the same `var-registry.final()` through the same `json.encode` — and a test compiles the example report and compares the attachment with a `typst eval` **field for field** rather than trusting it. That is also what made the choice reversible: had he picked (a) or (b), `from_pdf` would simply not be called and the tab would not change by a line.

  **The price, and why it is arguably a gain.** §1 makes everything computed in Typst **untraced**; this is the one artefact that now travels with those numbers, so a PDF handed to a checking engineer carries what produced it. What it is **not** is a second source (§2 rule 1): nothing reads it back into `data/`, and the report goes on computing its own values at every compile.

  **Three things measured before a line was written**, each of which would have sunk it. An attachment adds **no page**. It is **silently ignored for a PNG or SVG target**, so `build_examples.py`'s renders and the website's SVGs are untouched — and that one stopped being an argument and became a demonstration when the RFEM session re-froze **322 examples with the attachment in place** and `woodcore-document-1.png` and `-2.png`, the two that apply the rule, came out **byte-identical**. And it is deterministic, so an unchanged report still writes an unchanged PDF, the same reason `data/project.json` carries no date (§12).

  **Two findings worth the reading.** ⚠️ **Typst resolves an attachment's name as a path relative to the file that calls `pdf.attach`**, so what reaches the PDF is `_woodcore/lib/woodcore-variables.json`; Python matches on the **basename**, which stays right whatever a project calls its generated folder. ⚠️ And the freshness test is the PDF's **modification time against the newest source**, not the `stamp`: a PDF carries no record of the sources it was made from, so what can be asked is whether anything has been touched since it was written — a source saved in the same second reads as *not* current, which errs the safe way.
