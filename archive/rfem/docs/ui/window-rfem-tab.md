# The RFEM tab in docs/ui/window.md (§10quater), as it stood when it was retired (0.117)

**The RFEM tab (v0.98).** *RFEM* (group *Structure*, before *Modèles statiques*; `calc/tools/rfem_tab.py`, its words under `rf_`) is what the project's RFEM exports look like from inside Woodcore (§3.3duodecies). On the **left**, a tree: one row per export the project names (`gui.rfem_models` in the `.woodcore` file, `project.rfem_models`), and under it one row per structure — its name, or «sans nom» where it has none, with the members it holds as a range («24–29 (6)»). Under the tree, *Ajouter un modèle…* (an `.xlsx` inside the project), *Un dossier de .csv…*, *Relire* and *Retirer* — which takes the export out of the project's list and deletes nothing. On the **right**, cards: *Identité* (the file as the project names it, its size, when it was written, how long it took to read), *Contenu* (the nodes, members, surfaces, sections, load cases and combinations, and for a structure what it holds and which positions it realises) and *Problèmes*, every finding of `validation.py` written in the window's language from its own code — a `@position` on the wrong kind of object, a position `Positionen.xlsx` does not have, a section that disagrees with the workbook's, a `@load` naming no instance, a width past 100 m, a structure with no name.

⚠️ **It reads nothing by itself.** `on_shown()` deliberately does not re-read the exports when the tab is brought to the front, where the other editor tabs re-read their sources: an RFEM export is tens of megabytes and reading one is a second, so a tab switch must not cost that. *Relire* is the button that does it, and the *Import données* button reads every one of them as part of the export. ⚠️ An export that cannot be read — moved, renamed, half-synced by NextCloud — is listed with its error rather than dropped (`Export.read` never raises), so the row says what to fix. ⚠️ The buttons that need an export selected carry a tooltip saying so while they are disabled (`rf_needs_model`), the v0.79 rule for a disabled button. ⚠️ A `QFormLayout` is emptied with `removeRow` backwards and not with `takeAt`, which takes the item and **keeps the row**: the cards grew eleven blank lines per refresh until that was found (`clear`).
