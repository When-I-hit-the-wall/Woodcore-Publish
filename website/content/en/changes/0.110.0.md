# 0.110 — RFEM's internal forces, Python in the project, and checks written in plain words

This version also installs 0.100, which had no installer of its own. What follows is both together.

## New

- **RFEM's internal forces show in the RFEM tab at last**, and the report can print them. Three reasons stopped them, all fixed: no loading was picked by default; a design situation (SP1–SP4) drew nothing and said, wrongly, that the export carries no internal forces; and on the export's own row the figure card was hidden with nothing saying to choose a structure.
  - A **design situation is an envelope**: it carries the extremes and no curve. The note says so now and names `#rfem-max`.
  - Each situation's extremes are read **with the combination that produced them**, never enveloped a second time.
  - The curves are reconstructed exactly from the export alone.
  - Six commands — `#rfem-ids`, `#rfem-bars`, `#rfem-situations`, `#rfem-max`, `#show-rfem-combination`, `#show-rfem-forces` — each with its compiled examples on this site.
- **A button «Add to the static models»** under the figure: it writes that structure's presentation — the quantity and the loading being looked at — and re-exports, so that `#show-static-model("VU", diagram: true)` prints the very figure on screen. ⚠️ It writes a **presentation and not a model**: an imported model stays generated, and RFEM stays its source.
- **A Python tab.** You write Python there, you run it, and the right-hand pane shows the values your variables took — with no terminal to read.
  - `result("H_d", 2.2, "kN")` declares a result, which the report reads with `#val("H_d", domain: ("script", "portique"))`.
  - numpy is included; `numpy.linalg` solves any linear system.
  - A script **reads the project and writes nothing** but the results it declares.
  - Every export runs every script; a failure is a warning and never a stop.
- **A Formulas tab**, to write a check in plain words rather than in Typst: `column S001, N = -40 kN, l_k = 3 m, verify compression` becomes `#member("S001")` and `#verify-compression(...)`.
  - The words are recognised in English, French and German.
  - It is not an AI: the same sentence always gives the same Typst, and a line outside the grammar is refused naming the line.
  - The pane shows what you write, the Typst it becomes **and the page it compiles to**, and inserts into a section only after showing you what will be added.
- **The report's folder is named when the project is created** — «Static report» by default, following the language you choose, and without «(typst)». One language list sets both the document's and the engine's.
- **`style:` on `#var`, `#var-unit` and `#val`**, as on `#eq`: `#var("R_k", 7, "kN", style: "bold")` sets apart **the whole line** — `R_k = 7 kN` — and not the value alone. `"bold"`, `"underline"`, `"double"`.
- **The PDF carries the report's own variables.** `woodcore-document` attaches the whole registry to every PDF it writes, a few hundred bytes, so the Variables tab reads them in 0.7 s instead of compiling again.
- **More white around the headings** in `config.typ`: a section is set apart from what precedes it more than a sub-sub-section is.

## What changes in your reports

- **The numbers do not change.** Everything above is added; a report that calls none of it prints the same values.
- **The white around the headings changes the layout** of reports whose `config.typ` you take over: the pages reflow. It is the one new thing that moves something already printed, and it applies only to projects where you copy the four lines (see «To do»).
- **Existing projects are not renamed.** The report's folder is asked for only at creation; nothing is moved on disk in a project that already exists.
- **Your projects' engine becomes older**, so Woodcore offers to update it at the next opening — and only after that update does a PDF carry the variables attachment. Nothing breaks if you answer «Later».

## To do

- **Nothing is compulsory.**
- Answer yes when Woodcore offers to update a project's engine: that is what gives you the new commands and the Variables tab's fast reading.
- For the white around the headings in an existing project, copy the four `show heading.where(level: ...)` lines from the template into your own `config.typ`.
- For a script, open the **Python** tab, write your calculation, declare your results with `result(...)`, and read them with `#val(..., domain: ("script", "<id>"))`.
- For RFEM, open the **RFEM** tab, choose a structure and a loading, then «Add to the static models».

⚠️ **The Static models tab does not list imported models yet**: the button makes the model printable in the report, not editable in that tab.
