## 10bis. Typst API conventions — doc comments and function reference

The commands of `lib/` -- `formula.typ` and the `calc-engine*.typ` it imports, `positions.typ`, `sheet.typ` -- are the surface the engineer actually types against when writing `Sections/*.typ`. Three conventions keep it self-explanatory, and within reach, without forcing a re-read of `calc-engine.typ` every time:

**1. Triple-slash doc comments.** Typst treats `///` comment lines placed directly above a `#let` binding as structured documentation. Tinymist (the Typst LSP, used by the VS Code extension most engineers on this project already have) parses them and shows them as a hover tooltip on the function name — so the parameter list, types, and allowed values appear directly in the editor while writing `Sections/*.typ`, without opening `lib/calc-engine.typ`. Convention to follow for every public function in `lib/calc-engine.typ`:

```typ
/// One position on a line: its id in the colour of its type, then the fields asked for.
/// - id (str): the position's id, `"T001"`.
/// - label (none, str, content): a name of the call's own, printed after the id.
/// - category-show (str, array): the fields printed, in their order.
/// -> content
#let position(id, label: none, descr: none, category-show: ("type", "material", "strength-class")) = context { ... }
```

Once every public command carries this header, the Typst package `tidy` can generate a standalone reference page (HTML or PDF) straight from `lib/calc-engine.typ`, so the documentation can never drift out of sync with the code the way a hand-maintained doc file would.

**Documenting a command is part of writing it, and is not optional** (v0.64, §2 rule 14). A command is finished when Woodcore's commands tab can show it: a `///` block with a summary, one `- name (type):` line per argument, a `->` line, and at least two worked examples that compile — plus a category in `build_reference.CATEGORIES`, or a deliberate place in *Internes* for a binding nobody outside the engine should call. `tests/test_commands.py` fails on each of those separately, naming the command and its `file:line`, so a command cannot reach the report undocumented. 👉 The same rule is what keeps the *tab* honest: it lists what `lib/` defines, so a command left out of a category is a command a reader is told does not exist. Since v0.86 the obligation includes the translation: `calc/i18n/commands.json` carries each paragraph and argument in French and German, matched on the English it translates, and `tests/test_commands.py` names a unit whose English changed without it (§10sexies).

**A public command also carries its worked examples, in the same block** (v0.64). Two or three ` ```typ ` fences, each a fragment that stands on its own and names real ids of this project, set after the summary and before the `- param` lines. They are not decoration: Woodcore's commands tab **compiles** each of them and shows the page it produces (§10sexies), and `tests/test_commands.py` compiles them all, so an example that stops working is named rather than left to rot. One fence is one example — several in one fence would share a page — and a fence has to declare what it names, since each is compiled as a document of its own. The one that cannot be compiled at all is written ` ```typ-dry `, shown and never run.

👉 The convention now covers **all three files** `commands.typ` re-exports — `calc-engine.typ`, `formula.typ` and `i18n.typ` — and since v0.87 the fourth, `distance.typ`, whose helpers are listed under *Internes* though only `distance` reaches the sections (§10bis point 3); and every top-level `#let` in them, a state like `report-level` included. Until v0.64 the parser behind the workbook read the first file only and required a `(` after the name, so two thirds of the command surface was in no catalog at all.

**A command that prints takes `level:`; one that does not says why** (v0.120, spec `2026-10-20-indices-et-niveaux`, UI-003, ARCH-003). Every public command that prints a figure, a table or a list -- `show-*`, `verify-*`, `distance`, the `doc-*` and `sheet-*` objects -- takes `level: auto` with the meaning of docs/typst/report-engine.md §4 (1 alone, 2 with its legend and titles, 3 with its sources and citations); an argument its level decides takes `auto` as its default and is resolved with `at-level`, an argument written outranking the level. A public command taking none is named in `build_reference_lib.NO_LEVEL` with its reason (an accessor, a form's field, a document's table, a sheet's text…), and one whose levels print the same thing in `LEVELS_CONFOUNDED`, with its reason; tests/test_command_levels.py holds the two registries to the signatures both ways, and compiles each command at 1, 2 and 3. A new command is finished when it is in one of the two.

**Four rules the tooltip depends on, and `tests/test_doc_comments.py` holds them** (v0.63.1 — each was broken somewhere when the test was first run):

- **Every declared parameter carries a `- name (type):` bullet.** An argument the tooltip does not mention is one the engineer cannot find.
- **A command never hides its arguments behind a variadic sink.** `#let eq(..args)` shows in an editor as `eq(args: arguments) -> any`, and every named argument — `unit:`, `level:`, `style:` — is then invisible. Named arguments are declared one by one; only the *positional* tail may be variadic, which it has to be, Typst having no optional positionals (`#var("R_k", 7, "kN")` and `#var("q_k11", "q_(k,11)", 1.729, "kN/m²")` are the same command). `var`, `eq` and `val` were sinks until v0.63.1.
- **Every block ends in exactly one `-> type` line**, a union written with `|` — `-> content`, `-> int | none`. For a command that prints, `-> content` is not a formality: it is what says the result can go in a `grid` cell, which `Sections/005` relies on for its two load cases.
- **The block sits flush against its `#let`.** A single `//` line between the two detaches it and the editor then shows *nothing at all* — `render-symbol` had carried one since v0.49, so the one function whose whole job is explained in its header was the one with no header.

**2. A stable, predictable call shape.** Every `show-*` function that reads a calculation record — `show-calc`, `show-input`, `show-check` — keeps the same positional-argument order — **`domain`, then `instance`**, then whatever it looks up inside — with everything else passed as a named argument with a sensible default (`level: auto`, `title: auto`).

- `domain` is a calculation domain (`"snow-load"`, `"dead-load"`) or a domain carried by a position (`"bending"`).
- `instance` is the workbook sheet the domain was read from (`"SL-Dach1"`) or, for a position's domain, the position id (`"T001"`).

One rule covers both, because Python already knows which kind a domain is: `resolve-source()` looks the domain up in `data/calculations.json` first and falls back to reading it off a position. Since the spec 2026-10-21-commandes-typst-refonte the commands that rendered a calculation entire (`show-calc` and its siblings) are retired -- a calculation is written out into a file of its own and included, `#include domain-file(kind, id)` --, and the pair survives in `#var(key, domain: (domain, instance))`; the commands that take one id take it first (`#position("T001")`, `#image-positions-plan("Pavillon")`), and the named arguments surface through editor autocomplete instead of needing to be memorized. Combined with `assert(..., message: "...")` checks at the top of each function — e.g. rejecting an unknown `level` or an unknown `domain` with a message that lists the valid values instead of failing deep inside the rendering logic — a typo produces an immediate, actionable error rather than a silently wrong PDF.

**3. One import for every command** (v0.40). Every `.typ` file of the report starts with the same line — `#import "../commands.typ": *` in `Sections/`, `#import "commands.typ": *` in `Statischer Rapport.typ` — and never names the functions it uses. ⚠️ **In a project in three documents (v0.111) the line is written from the Typst root** — `#import "/commands.typ": *` in every entry file and every section, whatever its folder, and a picture `image("/Images/…")` — which is valid at any depth and is what Tinymist sees (§12), and is what will let a section be copied from one document into another without being edited; a project laid out as one report keeps the relative forms. ⚠️ **In a project laid out by folders (v0.119, issue #64) the files that configure the documents lie in `000-Typst-Config/`**, and the line is `#import "/000-Typst-Config/commands.typ": *` -- `calc/documents.py` spells it (`import_line`, `root_import_line`), from `Project.commands_typ`, and nothing else does (`tests/test_layout_literals.py`); the commands.typ there imports the engine as `"/000-Woodcore/lib/calc-engine.typ"`. What a template, a form or a content template writes keeps the root form (`"/commands.typ"`, `"/Template/…"`), which the creation of a project rewrites (`documents.relocate_config_paths`), as the migration rewrites a project's own. The report's `commands.typ` re-exports the whole of `lib/calc-engine.typ` and `lib/formula.typ` — the engine's copy in `_woodcore/lib/` since v0.82 (§12) — (and, through the first, `lib/i18n.typ`) with a wildcard, so a function added to the engine can be called in every section at once, and no import line is edited again when a command is added or renamed (§13). One rule follows for the engine: every top-level binding of those files reaches every file, its helpers included, so none may take the name of a Typst global (`text`, `table`, `h`, `round`, …), which it would then replace in every section and not only in the engine. Several names are not hyphenated — `var`, `eq`, `val`, `unit`, `verify`, `t`, `tl` among them — and none is a Typst global, checked against `dictionary(std)` at v0.77; another library file would be re-exported from `commands.typ` the same way. ⚠️ `lib/distance.typ` (v0.87), `lib/timber.typ` (v0.88), `lib/bibliography.typ` (v0.99) and `lib/document.typ` (v0.112) are the exceptions to the wildcard, deliberately: `lib/formula.typ` imports their commands **by name** — `distance`, the nine member checks, `show-bibliography`, `cite-norm` and `bib-note`, and the eleven commands of the documents' objects (§3.3octodecies) — so `commands.typ` exports those and none of their helpers, and `commands.typ` itself did not change. The chain `calc-engine.typ → bibliography.typ → distance.typ → formula.typ` is acyclic by construction: `bibliography.typ` imports from `calc-engine.typ` and from nothing else; and `document.typ` imports `calc-engine.typ` and `bibliography.typ` at its top and nothing from `formula.typ` — a value in a cell is `doc-value`'s, which reads the registry and the export through `calc-engine.typ`'s own lookups — so no import stands inside a body.

**Function reference table.** Every public command of `lib/` carries the `///` header described above; the reference the window and the site show is generated from those headers (`calc/build_reference.py`, §10sexies), and this table is the overview: what each does in one paragraph, and a call. Since the spec 2026-10-21-commandes-typst-refonte a calculation is written out by Woodcore into a file of its own and included (`#include domain-file(kind, id)`), a drawing is an image set in a native figure, and the documents and the export sheets are raw Typst: the `show-*` commands, `#val`, `#member`, `#calc-block`, the `doc-*` and the `sheet-*` objects are retired -- the table after this one says what each becomes.

| `var` | `var(key, ..rest, value: none, unit: none, domain: none, display: auto, style: auto, role: auto, label: none, label-position: auto, descr: none, descr-position: auto, norm: none, norm-section: none, norm-position: auto, id: none, level: auto)` | Writes one variable down -- `key`, then optionally its printed symbol, its value and its unit, positional (`#var("R_k", 7, "kN")`, `#var("q_k11", "q_(k,11)", 0.8, "kN/m²")`) -- stored under `key`, where every formula below names it, and printed (§10quinquies). Since the spec 2026-10-21-commandes-typst-refonte it is **the one command that prints a value** (REQ-009): `#val`, `#var-unit`, `#show-input`, `#var-of` and `#value-of` are merged into it. **`domain:` says where the value is read**: a **pair** is a calculation of the export and its instance (`("snow-load", "SL")`), read live, and falls back to the `#domain` named after that instance for a name the export does not carry; a **string** is a `#domain` of the report, and the variable is copied out of it into wherever the line stands. Either way the var of this same `key` is taken with its unit, its symbol, its description and its citation -- `label:`, `norm:` and `norm-section:` still override what it carries. `#var(key)` alone reprints a variable declared above; a value written beside a `domain:` is a literal **checked** against the export, said in red where they part (ARCH-007). **What is printed, and where** is said by fine arguments (REQ-001): `display` -- `"none"`, `"variable"`, `"value"`, `"value-unit"`, `"variable-value-unit"` --, and `label-position`, `descr-position`, `norm-position` -- `"none"`, `"before"`/`"after"` on the line, `"footnote"`, `"in-line"` in grey, `"line-right"` in the right-hand column. A **level** is a preset of them (`lib/display-presets.json`), and an argument written wins over it; `#calc-defaults` sets them for the next line, a domain or the document, and `presets: "block"` is the family a file Woodcore writes out opens with (Q-014). `style:` -- `"bold"`, `"underline"`, `"double"` -- sets the whole line apart. `role: "result"` lists it among the results `#var-table(role: "result")` gathers. `id:` marks a line Woodcore wrote; a line without one is the engineer's (Q-006). ⚠️ There is no `#let`: Typst gives a function no way to bind a name in its caller's scope, so the name is the string. | `verify` | `verify(relation, display: auto, role: auto, label: none, label-position: auto, descr: none, descr-position: auto, norm: none, norm-section: none, norm-position: auto, id: none, level: auto)` | States a relation between the report's variables, **performs it**, and marks the answer — double-ruled in green with a ✔ where it holds, in red with a ✘ where it does not (§10quinquies). The relation is a raw block naming the registry's keys, and either side may be a whole expression, read by the parser `eq` uses. **The printed sign follows the truth**: where `a <= b` does not hold the line prints `a > b`, so what is written is true and the ✘ is what says the relation the report *wanted* is not the one that holds. Level 0 prints nothing (the comparison is still made), 1 the symbols alone, 2 the numbers alone, 3 both — with the right-hand side reversed, `F_Ed = 2.037 kN ⩽ 4.969 kN = R_d`, so the two numbers meet in the middle of the line; a side that is a **whole formula** prints at level 3 its letters, the same with numbers and units, then its value, `F_Ed/R_d = 12 kN/24 kN = 0.5 ⩽ 1`, and a bare number the number alone (v0.87). A `*` multiplies, as `dot` does. The comparison is made on the **full** values, a tie absorbed at a relative `1e-9`; two sides of different dimensions stop the compile. Replaced `test` in v0.61, and is **not** called `eval`, which is a Typst global (§10bis). ⚠️ Untraced, and it carries no citation — the prose must, if it matters. | `#verify(`F_Ed <= R_d`)` |
| `eq` | `eq(key, ..rest, unit: auto, as-unit: none, value: auto, display-formula: auto, display-equation: auto, style: auto, role: auto, label: none, label-position: auto, descr: none, descr-position: auto, norm: none, norm-section: none, norm-position: auto, id: none, level: auto)` | A calculation written **by hand**: the formula in letters, the same formula with the numbers and their units put in, and the answer **computed from the formula** — with a real unit algebra (§10quinquies). The result is stored under `key`, so the next line names it without redeclaring anything. The formula **names the registry's keys** and nothing else: there is no `where:`, and a name the registry does not hold stops the compile listing the names it does. Only whole words are substituted, longest key first, so `F` cannot eat the `F` of `F_Ed` nor the `n` of `ln`. `unit:` is optional: left to itself the answer comes out in the one unit the table names for that dimension — kN, kNm, mm, N/mm², … — which `#unit` sets (§10quinquies, v0.63). Given a unit of **another** dimension it does not stop: the answer is printed in the unit the operands were written in (an N times a mm is an `Nmm`) with a red line naming both. Level 0 prints nothing (the answer is still computed, checked and stored), 1 the symbol and the answer, 2 also the formula in letters and the `label:` (v0.85.1, what the answer *is*, printed after it as `#var` prints its own), 3 also the formula in numbers, the `descr:` as a footnote and the citation. ⚠️ The signature is `eq(key, ..rest, …)` (corrected v0.117, the table having said `eq(key, symbol, formula, …)`): `..rest` holds the optional printed symbol, then the formula, Typst having no optional positionals. It takes the fine arguments `#var` takes -- `label`, `descr`, `norm`, `norm-section` and their `*-position` -- and `display-formula` and `display-equation` for what of the formula is printed (spec 2026-10-21-commandes-typst-refonte, REQ-001), each overriding what the level would print; the level is a preset of them (`lib/display-presets.json`), which reproduces what is described here. **A formula too wide for its row is stacked at its `=` signs** (v0.87, second half, §10quinquies): the symbol and the formula in letters on the first line, then `= <numbers> = <answer>` on as few lines as the width holds, each `=` under the first, the lines spanning the citation column and the citation standing at the end of the first; a formula that fits is set exactly as before. A **`*` is a product**, evaluated and printed as `·` (`star-as-dot`, v0.87), and the symbol may carry its words unquoted — `"G_(1,Ed)"` for `"G_(1,\"Ed\")"` (`quoted-words`). A sum of different dimensions, a `sqrt` of an odd power, an unreadable unit, a `value:` the formula contradicts: each stops the compile naming both sides. A formula that cannot be evaluated still prints, with `value:` giving the answer — and its unknown words are then expected rather than refused. `style:` names a math function applied to the answer — `"bold"`, `"underline"` — or **`"double"`** (v0.85), which rules it twice underneath in the document's own ink: `verify`'s own mark, for a result a section ends on. ⚠️ The unit is a **named** argument and cannot be a third positional, where `var`'s is the last one: a formula may be written as a string, so with two positionals a unit and a formula are the same shape and nothing could tell `#eq("eta", "F/R", "%")` from a symbol and a formula — a value, which is what `var` takes, is never a string. `%` is a unit like any other here, dimensionless with a factor of 0.01, so `unit: "%"` prints 0.741 as 74.1 %, and per mille is written `"%%"` -- two signs one after the other, as the keyboard has them -- and printed ‰ (`unit: "%%"` prints 741 ‰, the engineer, 22.10.2026); without `unit:` a ratio stays without one; `#unit("%")` stays refused, since it would make every dimensionless result a percentage. `role: "result"` lists the answer among the results `#var-table(role: "result")` gathers (Q-009); `as-unit:` gives the answer the unit of another dimension where the engineer means it, said in the window. ⚠️ Untraced, like everything computed in Typst (§1), and it checks dimensions, never sizes. | `` #eq("R_d", `k_dens dot eta_w / (gamma_M \/ eta_M) dot R_k`, style: "bold", norm: "Sherpa") `` |
