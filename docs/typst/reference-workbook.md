# Generated reference workbook

> docs/typst-reference.xlsx and the call_* functions that spell every Typst call.
>
> Moved verbatim from CLAUDE.md (§10ter) on 2026-10-07. The § numbers are kept as stable anchors: `docs/README.md` maps every § to its file.

## 10ter. Generated Excel command reference (docs/typst-reference.xlsx)

`lib/calc-engine.typ`'s `///` doc comments (§10bis) drive editor hover tooltips, but an engineer writing `Sections/*.typ` also needs, without opening any JSON, the literal strings to type as arguments -- which `domain`/`instance`/`check-name`/var `name` exist right now, and which discrete `choices` a var like `ce` accepts. `calc/tools/build_reference.py` answers that by generating a workbook, `docs/typst-reference.xlsx`, with one sheet per concern (`Functions`, `Parameters`, `Calculations`, `Results`, `Steps`, `Checks`, `Vars`, `Choices`). Every row that corresponds to a real `show-*` call carries an `example_call` column with the exact literal string to paste, e.g. `#show-calc("snow-load", "SL-Dach1")`.

Since v0.18 every sheet that catalogues a calculation — `Calculations`, `Results`, `Steps`, `Checks`, `Vars`, `Choices` — leads with `source_type` / `domain` / `instance`, the two arguments that address any `show-*` call, so a calculation read from a **workbook sheet** is catalogued alongside one carried by a position. One `iter_sources()` helper enumerates both kinds, so no sheet can list one and forget the other. Two consequences of the v0.18 call shape are visible here:

- the **`Loads` sheet is gone** — there are no load ids left to list, and `Calculations` (one row per domain+instance, with its `engine` and its counts) plus the new `Results` sheet (what each instance prints at level 1) say strictly more;
- the **`Steps` sheet has no `example_call`** — `show-calc` renders a calculation entire, so a step is never addressed by name. It keeps `order`, `formula` and `uses` instead, which is what a reader actually wants from it: the sequence the report will print.

👉 **Since v0.64 it reads all three files of `lib/`, and every binding in them** (§10sexies) — four since v0.87, `distance.typ` among them (`build_reference.LIB_FILES`). `Functions` carries every top-level `#let` — the internals included, marked as such — each with its `category`, its `file`, its `line`, its `kind` (a function or a setting), its `returns`, and the two calls the commands tab copies; `Parameters` gains the `category` and the `default` read out of the signature; and a new **`Examples`** sheet gives each worked example with a `compiled` column saying whether it is one the tab renders. This is what restored the 26 commands that had never appeared here — `var`, `eq`, `verify`, `val`, `unit`, `var-domain`, `var-unit` and the ten of `i18n.typ`, which is to say the whole of v0.60 and v0.61. `call_complete` and `call_minimal` join the `call_*` roll below.

👉 Since v0.10 this workbook has **no `Positions` or `Sections` sheet**: those duplicated `Positionen.xlsx`'s own `Positions` sheet (the actual problem that prompted removing them) without adding anything a reader couldn't already get from `Calculations`/`Steps`/`Checks`/`Vars`. The two workbooks are now strictly non-overlapping: `Positionen.xlsx` is the only hand-edited one, `docs/typst-reference.xlsx` the only generated one.

👉 Like everything in `data/`, **`docs/typst-reference.xlsx` is generated, never hand-edited**: `calc/export_all.py` regenerates it on every run, after all of `data/*.json` has been written and validated (§12), so after every full export it reflects exactly the domains/instances/steps/checks/vars that will compile successfully. A connector, a connection, a plan, a static model or a schema saved in Woodcore exports its own part of data/ and not this workbook, whose sheet for it then lags until the next *Importer Excel*. It is versioned in Git (like `data/*.json` and `out/*.pdf`) for the same traceability reason (§1bis). It is written only when something in it other than the save time openpyxl stamps into `docProps/core.xml` differs (v0.78), so an export that changes nothing leaves the committed file as it was and a run of the test suite no longer leaves it modified. It can also be regenerated on its own, without rerunning the whole data pipeline, via `python calc/tools/build_reference.py`.

👉 **A Typst call is spelled out in one place** (v0.28): `build_reference.py`'s `call_*` functions — `call_show_calc`, `call_show_input`, `call_val` (v0.80, in place of `call_inline_value` and `call_live_load`), `call_var` (v0.61), `call_var_of`, `call_value_of`, `call_show_check`, `call_instance_loop`, `call_show_polar_moment` (v0.31, `call_show_fastener_forces` until v0.32, `call_show_fastener_polar_moment` until v0.38), `call_show_connector` (v0.33), `call_show_connector_resistance` and `call_connector_loop` (v0.68), `call_show_schema` and `call_schema_loop` (v0.72), `call_var_registry` and `call_find` (v0.100, for the variables tab: a variable the **report** declared, carried out of the column that computed it, and what there is to name in one domain — `call_var` reads a calculation of the *export* instead, which is the one thing that tells the two apart), `import_line` — build every call as text, escaping the strings they quote. The `example_call` columns go through them, and so does Woodcore (§10quater), so the workbook and the window cannot write the same call two ways; when a signature in `lib/calc-engine.typ` changes, these functions are what follows it. The `Calculations` sheet also carries each load domain's `action` (§3.3). Since v0.31 every sheet lists the connections too (`source_type` `connection`, domain `connection`, the id as instance — `iter_sources()` enumerates them with the rest), and a `Connections` sheet gives each one's n, I_p,x, I_p,z, I_p, its citation and its `show-polar-moment` call. Since v0.33 a `Connectors` sheet lists the connectors of `data/connectors.json`: each one's type, assembly, diameter, length, dimension, steel, predrilling and elements, and its `show-connector` call. Since v0.76 the `Connections` sheet names each connection's schema where it named its connector, and the `Connectors` sheet lists the polar moments drawn on the same schema where it listed a connector's calculations. Since v0.34:
- `call_show_plan`, `call_show_plan_legend`, `call_plan_loop` and `call_calc_block_plan` spell the plans' calls;
- the import line gained `show-plan`, `show-plan-legend`, `plan-ids` and `calc-block`;
- a `Plans` sheet lists each plan: its label, floor, background, scale, elements, axes and labels, the labels Positionen.xlsx lacks, and its `show-plan` call.

Since v0.40 `import_line()` writes `#import "../commands.typ": *`, the one line every section starts with (§10bis), and names no function: `IMPORT_NAMES`, the list of names it used to join, is gone with `ENGINE_IMPORT_PATH`, and the line cannot fall behind the engine any more.

Since v0.51 `call_show_static_model` and `call_static_model_loop` spell the static models' calls, and a `Statics` sheet lists each model: what it is built of, what its loads show, what its dimensions measured (v0.55), the variables of the export their numbers came from, and its `show-static-model` call (§3.3octies). Since v0.49 `call_show_live_load` spells the Nutzlasten's own call and `call_val` the two values inside a sentence (§3.3septies; `call_live_load` until v0.80); `iter_sources()` marks an instance read from a norm table `source_type` `norm` rather than `sheet`, so a category of Tabelle 8 is catalogued beside the sheets it is addressed like; and the `Calculations` sheet's `example_call` is `show-live-load` for a category that has values, `show-calc` for the one that does not (E), which the report refuses. Since v0.72 a `Schemas` sheet lists each detail schema: its label, how many elements, connector markers, aids and dimensions it carries, the ids of its elements and markers, the elements whose position no longer resolves, and its `show-schema` call; and since v0.74 the `Connectors` sheet also names each connector's schema, its members' elements and its markers.
