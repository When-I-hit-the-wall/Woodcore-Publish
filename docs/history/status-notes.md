At **α = 0** the check is the section alone, σ_c,0,d = N/A ⩽ f_c,0,d (4.2.2.1, equation (10)) and **no buckling** — buckling is the future «Flambage» module —, through the new argument **`stability: false`** of `#verify-compression` (the default, true, is unchanged: both buckling lengths are needed, the «Stabilität» part is printed, η is the largest of the section's and the two axes'); at **α = 90°** equation (11) and between (12) with f_c,α,d of (13), through `#verify-compression-perp`. The resistance f_c,90,d is chosen among **five entries** of SIA 265 Tabelle 8/9: *Général* («generell»), *Avec avant-bois* (at least 100 mm of timber on both sides) and *Appui d'extrémité*, the last two each *avec* or *sans conséquence sur l'élément porteur* — «sans conséquence» being the bracketed value (Tabelle 8 note 4, «grössere Eindrückungen»: larger indentations provably without influence on the load-bearing member), greyed for a grade that has none (D30). The source gained `case`, `larger`, `l` and `w` (`w` null follows the section's width b; the schema stays **1.0**, the fields being additive) and the record `case`, `larger`, `l`, `w`, `w_from`, `case_label` and `f_c_90_table`; the example project carries **DR-01** (α 90°, Endauflagerung, l 120, on T001, F 16 kN, η 0.93) and **DR-02** (α 0°, GL24h 140/140). ⚠️ **The results in the window are an instant Python calculation, REVERSING the same day's «Typst alone»** (§13): `member_check.compute(record)` reproduces exactly what `lib/timber.typ` computes — the rows with their registry keys, symbols, values and units, η, the verdict, the equation and the clause — with every value of SIA 265 read through `calc/norms`, and `tests/test_member_check.py` compiles 17 records at level 0 and holds every row equal to Typst's registry within 1e-6. **The report is unchanged**: the calculation it prints is Typst's, Python's only feeds the window. ⚠️ **The right pane** is reworked: «Résultats» first (instant, symbol = value unit, the clause and the equation, the verdict η ⩽ 1 ✔ in the new theme token `ok` or ✘ in `danger`), then «Commande Typst» with «Copié ✓», then «Options de la commande» and «Aperçu Typst» as **collapsible sections closed by default** — the preview compiles **only while expanded**, and open or closed is kept in `view_state`. Beside them: `#var-unit("F", "N")` carries a variable already declared into another unit and prints it, `#var("F", var-of(...), "N")` **converts** where it used to relabel the number silently, and past 99 999 a number written by hand is printed `1.235 · 10⁶`. ⚠️ The accepted price of one unit per dimension: a stress and a surface load *are* one dimension, the default serves the stress, and a line that wants the other says so. ⚠️ The scientific notation is confined to `lib/formula.typ` on purpose — `fmt-decimals`, which `show-calc`, the tables and the figures print through, is untouched. **And the commands now say what they take**: `#eq`'s editor tooltip read `eq(args: arguments) -> any` and mentioned none of its arguments, because `var`, `eq` and `val` swept everything into one `..args`. Their named arguments are declared one by one now, only the positional tail staying variadic; the five public commands that carried no header at all have one; `render-symbol`'s header, detached from its `#let` by a stray `//` since v0.49, is attached again; every block ends in a `-> type` line; and `tests/test_doc_comments.py` holds all four rules, each verified against a planted defect (§10bis, §11ter).

> **Also in v0.62 — the Katalog imports and exports: two split buttons (§10quater).** The window could relaunch the pipeline but never compile the report, so the PDF meant leaving it for `build.ps1`, `make` or Tinymist. *Réexporter depuis Excel* is **Importer Excel** now — the same operation, named as the engineer performs it rather than as the pipeline sees it — and beside it sits **Exporter PDF**, which runs the export and then `typst compile`, in that order and only in that order: Typst is never compiled against unvalidated data (§12), so a failed export stops the chain with the exporter's own message and nothing is compiled. Each is a **split button**: the button itself acts, its little arrow opens a menu. The PDF menu holds what `build.ps1` puts in `-Level`, `-Uniform` and `-Language` — a base level 1/2/3, a uniform level 1/2/3, a language de/fr/en — as **checks and never actions**: choosing one says what the next compilation will carry, and nothing runs until the button is clicked, which is what lets a level and a language combine. The seven level entries share one exclusive group across both submenus, so the rule `build.ps1` can only state by throwing when it is given both — `-Level` and `-Uniform` are mutually exclusive — is one the interface cannot express at all. The import menu holds a single entry, the button's own: there is one way to import, the `make data` the Makefile names, and the arrow says so rather than hinting at others. A compilation that succeeds **opens the PDF**, and the button's tooltip names what is checked while anything is (`Réglages : Uniforme 2 · Français`), so a forced level cannot be left on unnoticed. ⚠️ `-AllLevels`, the `report-N` variants and `-SkipData` stay out, so every export from the window writes the one deliverable, `Statischer Rapport.pdf` beside the workbooks, and always re-exports first — §12's three routes still name one target. ⚠️ The choices are **not** written to `settings.json`: a forced level remembered from another day is one nobody would look for, so the menu opens at *tel qu'écrit* every launch and keeps its state only across a rebuild.

> **Also in v0.61 — one name per variable: `var`, `eq`, `verify`, and a registry (§10quinquies).** v0.60 gave the report a calculation it could compute; it was unreadable, because a variable carried **three** names — the Typst binding `k-dens`, the `where:` key `k_dens`, the printed symbol `k_"dens"` — which had to agree and which nothing checked. They are one name now. `#var("R_k", 7, "kN")` writes a variable down and prints it; a formula **names the registry's keys** — `` #eq("R_d", `k_dens dot eta_w / (gamma_M \/ eta_M) dot R_k`) `` — so there is no `where:` and no `#let`. `#verify(`F_Ed <= R_d`)` states a relation, performs it, and **prints the sign that actually holds**, the ✘ saying the wanted one does not. `#var-domain("…")[ … ]` keeps two columns' variables apart *without losing them*: a domain is a key, never popped, so `#val("…", "M")` reads one back further down the page. The unit of a result need not be declared any more — the engine picks the one an engineer writes, so `M_Ed / a` comes to `2.037 kN` and not `2037.037 N` (v0.61 chose it from a list on the value's size; v0.63 gives each dimension one unit and lets `#unit` set it). ⚠️ `#var` **cannot create a Typst binding** and no later version will change that: a function cannot bind a name in its caller's scope. ⚠️ Still **untraced**, like everything computed in Typst (§1), and it checks **dimensions, never sizes**.

The numbers line is *derived* from the first — `show-calc` substitutes each operand the step's own `uses` names — so a printed number can never drift from the symbol it stands in for, the way a hand-typed substitution would. `show-calc` also stops rendering "every input, then every step": it walks a calculation **var by var, in the order the data states them**, printing a var some step produces as that step. Both the order and the level split are therefore data rather than display code — a var and the step that produces it carry *separate* `level`s, so a value can appear from level 2 while the working behind it waits for level 3. Bold is the **answer**, not the working: only a step producing one of the calculation's `results` sets its numbers line bold, so `q_k` stands out and `h_ref = 438 + 200 = 638 m` reads as the intermediate it is. Two more consequences worth knowing: an intermediate step's operands are not set out on rows of their own, since its substituted formula already shows them, while a *result* step's operands keep their row and their footnote; and a formula stating a **bound** rather than an equality (`s_k = ... >= 0.9 kN/m²`) cannot be closed with `= result`, so it keeps the compact `mit h_ref = ...` note — set *after* the formula on the same row, not under it.
