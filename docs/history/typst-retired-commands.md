# The reference rows of the retired commands

> Moved verbatim from `docs/typst/api-conventions.md` §10bis, «Function reference table», on 2026-10-22: the commands the spec `docs/requirements/completed/2026-10-21-commandes-typst-refonte.md` took out of `lib/` (lot 19). What a call of each becomes is `calc/renamed-commands.json`, which `calc/domains/commands_migrate.py` rewrites a project from and the export refuses an old call by; `docs/typst/api-conventions.md` §10bis prints it as a table.

| Function | Signature | What it does | Example |
|---|---|---|---|
| `calc-block` | `calc-block(positions, title: none, axes: none, description: false, level: auto, plan: none, body)` | Groups every calculation concerning the same position(s) into one framed block, headed by each declared position's summary and axes (§5). `positions` is one id or an array; `axes` is one string for all of them or one entry per position; `description` is passed through to each header's line, `#member`'s at level 1 since v0.94 (`show-position`'s until then). `plan: auto` shows, under the summaries, a detail of every position plan the block's positions are drawn on, with them highlighted; a plan id shows that plan (§3.3sexies). Every `show-*` call in `body` that reads a *position* is checked against the declared positions and panics if it reads one the block does not declare; a call reading a calculation domain's sheet is not checked (§8). Blocks nest. | `#calc-block("T001", title: "Schneelast", axes: "Achse X3 / Achse YC")[ ... ]`, `#calc-block("T001", plan: auto)[ ... ]` |
| `show-calc` | `show-calc(domain, instance, level: auto, title: auto)` | Displays **a whole calculation**, walked **var by var in the order the data states them** — so the sequence the report prints is a property of the data, not of this function. A var some step produces is rendered as that step: its `formula` in letters (carrying the norm citation and the step's `description` footnote), then the same formula **in numbers, set bold**, built by substituting each operand the step's `uses` names. A var no step produces is one row, `symbol = value`, with its `description`/`choices` footnote from level 2 — or *half* a row, where consecutive vars share a `group` (§3.3) and are joined by a semicolon (`C_e = 1; C_T = 1`), optionally named by a `group_label` on the var that opens the run (`Gebäude Geometrie: L = 20.18 m; B = 7.8 m`) or, since v0.84, by one on a var that *joins* a run already open, which names itself inside the row (`Bauteil 1: ρ_(k,1) = …; Bauteil 2: ρ_(k,2) = …`). A step that declares itself `inline` prints its letters, its numbers and its answer on **one** row instead of two; a row too wide for its width — that one row, or the numbers line of a step on two — is **stacked at its `=` signs** under its first line, as `#eq`'s formula is (v0.87, second half, §10quinquies), and a row that fits is set as before. A var that declares `keep` holds its row even where an intermediate step's substituted formula already shows its number (§3.3). A var that carries a **`heading`** puts a line of its own above the first row it prints — «Charakteristische Lochleibungsfestigkeiten für C24:», the block the Bemessungsbeispiele name before a run of formulas — and nothing at all where that row is not printed (§3.3). Bold marks the answer and only the answer: a step whose result is in `results`, or which the data marks `bold` (§3.3), sets its numbers line bold, an intermediate one does not — and the same predicate decides whose operands keep their rows. Two rules keep that from printing anything twice: an **intermediate** step's operands get no row of their own (its substituted formula already shows them), while a **result** step's operands — C_e, C_T, μ — keep theirs; and a formula stating a *bound* (`s_k = ... >= 0.9 kN/m²`) is not closed with `= result` but keeps the compact `mit x = ...` note, set after the formula on the same row, above a plain result row. `level` selects what is printed, but **which** value appears at which level is the data's decision: a var and its step carry separate `level`s (§3.1), so `h_ref` shows as a value from level 2 and grows its formula only at level 3 (§3.3bis). Each of the instance's `tables` is printed at the level *it* declares and on the side *it* declares (§3.3), in list order: above the values as the working behind them, its `totals` rows what the lines below carry forward, or below them as the answer they lead to, its `value` cells naming the vars it prints so those vars get no rows of their own. A result is never allowed to go missing: one no shown step produces is printed anyway. There is deliberately no step-name argument — `show-input` is what picks a single intermediate value out. `title: auto` heads the block with the instance name (what tells two cases of the same load apart), `none` prints no heading, a string replaces it. An unknown `domain` panics listing both the valid domains and the valid positions; an unknown `instance` raises an assertion error listing the valid ones. A *position* instance is scope-checked against the enclosing `calc-block` (§5); a *sheet* instance is not (a load belongs to no position, §8). | `#show-calc("snow-load", "SL-Dach1")`, `#show-calc("dead-load", "EL+AL-Fassade", level: 3)` |
| `show-input` | `show-input(domain, instance, name, level: auto)` | Displays one input variable as `symbol = value unit`, with its `description` and `choices` as a single footnote at `level >= 2` (§9). The one call that reaches for a named value: `show-calc` renders a calculation entire and never takes a var name, so this is how a report pulls one intermediate value into its own prose. An unknown `domain`, `instance` or `name` fails with the valid options listed. | `#show-input("snow-load", "SL-Dach1", "h_ref")` |
| `val` | `val(what, domain: none, type: "val+unit", unit: none, symbol: none, level: auto, label: none, descr: none, norm: none, norm-ref: "", note: "footnote", style: none)` | **One value, printed** — wherever it comes from, and the one command that prints one (§10quinquies, v0.80, which folded `fmt`, `inline-value` and `live-load` into it). `what` is a variable's name, a var object (`var-of(...)`, an earlier `#var`, an `#eq`) or a number written here; `domain:` says where a name is read — left out the innermost `var-domain` and then the report's own variables, a string that `var-domain`, a **pair** a calculation and its instance (`("snow-load", "SL")`, `("live-load", "A1")`). `type:` picks the part: `"val+unit"` (the default) `1.729 kN/m²`, `"val"` `1.729`, `"unit"` `kN/m²`, `"expression"` `s_k = 1.729 kN/m²`. Level 0 prints nothing, 1 the value, 2 adds the label, 3 the description with its choices and the citation, all as **one** footnote — inline there is no em dash to hang a label on and no column for a citation, so `level: 1` is what keeps a bare number in a sentence of a checking report. **`note: "line"`** (v0.87) sets them on the line instead, `value — label (description; citation)`, the `choices` and the orange line of a unit written over staying a footnote. `unit:` prints the value in another unit **without touching the one it is held in**, and says so in an orange footnote whose marker is orange too; a unit of another dimension is refused. `label:`/`norm:`/`norm-ref:`/`symbol:` state what a value carries none of, or replace what it does. **`style:`** sets whatever part it prints apart, as `#var`'s line is (v0.100). Inside a `var-line` it is one item of the row. | `#val("R_d")`, `#val("s_k", domain: ("snow-load", "SL"), type: "expression")`, `#val("q_k", domain: ("live-load", "A1"))`, `#val("I_p", domain: ("connection", "SD_01-8mm"), unit: "cm²")` |
| `var-line` | `var-line(label: none, norm: none, norm-ref: "", level: auto, sep: auto, body)` | Sets several declarations on **one line**, joined the way `show-calc` joins the vars of a `group` (§3.3): `R_k = 7 kN; k_dens = 0.806; γ_M = 1.7` (§10quinquies, v0.80). `#var`, `#var-unit`, `#eq`, `#val` and `#verify` each know they are in a row: they print inline, and their own label and citation become one footnote. **The engine writes the separators**, so a value a level hides takes its separator with it and a `;` is never typed after a `#var(...)`, where Typst swallows it. `label:` names the row before its first value, as a var's `group_label` does; `norm:` cites the whole row in the right-hand column; `level:` overrides every item's own — `level: 0` declares the variables and prints nothing at all, not even the space of a line; the row's own citation follows its items', in the column from level 3 (v0.85.1); `sep:` replaces the semicolon. | `#var-line[ #var("R_k", 7, "kN") #var("k_dens", 0.806) ]`, `#var-line(label: "Teilsicherheitsbeiwerte", norm: "SIA 265", norm-ref: "2.2.5")[ … ]` |
| `show-check` | `show-check(domain, instance, check-name, level: auto)` | Displays one entry of a calculation's `checks[]` (utilization ratio + status), following the same `(domain, instance)` shape and the same `calc-block` scope check. `level` is accepted for a consistent error on a bad value but currently unused — every check renders the same regardless of level, reserved for a future per-check detail split. | `#show-check("bending", "T001", "Bending utilization")` |
| `var-of`, `value-of` | `var-of(domain, instance, name)`, `value-of(domain, instance, name)` | Data access, not display: the whole `var` object, or just its number, so a value can be **computed with** in Typst and bound to a reusable `#let`. Carries no `calc-block` scope guard — that guards what is printed under a header, not what is read into a variable — which is also what lets these work outside `context`, i.e. in a plain `#let`. Prefer `var-of` when the same variable is also displayed, so it is looked up once. | `#let s-k = var-of("snow-load", "SL-Dach1", "s_k")` then `#let x = get(s-k, "value") * 0.65` |
| `var-unit` | `var-unit(key, unit, label: none, descr: none, level: auto, norm: none, norm-ref: "", note: "footnote", style: none)` | Converts a variable already declared into another unit **and prints it**, the way `#var` prints — which is what its name says, and why it is not called `change-unit` (§10quinquies, v0.63). From there on every formula naming it substitutes the new unit. It is written back where the name lives, so a conversion inside a `var-domain` converts the variable instead of shadowing it. A unit of another dimension leaves the value untouched and prints the red line `#eq` prints; a name the registry does not hold, and a unit that cannot be read, stop the compile. It takes `#var`'s **`style:`** too, its line being `#var`'s line (v0.100). Its levels are `#var`'s: 0 prints nothing and converts all the same, 1 the line, 2 also the label, 3 also the description and the citation — and so is its placement since v0.87, inline with one footnote, or on a line of its own with `note: "line"`. **`label:`, `descr:`, `norm:` and `norm-ref:` are `#var`'s** (v0.87, second half): given, they override what the variable carries and are **stored with it**, so a `#val` or a `#find` further down reads the label the conversion gave; `norm-ref:` alone replaces the clause and keeps the norm. | `#var-unit("F", "N")`, `#var-unit("I_p", "cm²", label: "Polares Trägheitsmoment", level: 3)` |
| `var-domain` | `var-domain(name, title: none, gen: none, body)` | Keeps one set of variables apart from another **without losing it**: what is declared inside belongs to `name`, and stays readable further down the document through `val(key, domain: name)` (§10quinquies). A domain is a *key* in the registry and is never popped — only the current-domain marker is — which is what tells it from a scope that unwinds. A name resolves in the innermost domain first and then in the default one, so what a section declares outside every domain (R_d, a partial factor) is nameable inside all of them. 👉 A *domain* here is a set of names in the report; it has nothing to do with a calculation domain (§3.3), which is a kind of calculation whose instances are Excel sheets — and `val`'s `domain:` takes either, a string for the one and a pair for the other. | `#var-domain("S10 - 0.55 kN Ende")[ … ]`, `#val("M", domain: "S10 - 0.55 kN Ende")` |
| `member` | `member(name, b: auto, h: auto, d: auto, grade: auto, moisture-class: auto, position: auto, impact: false, k-h: true, description: false, axes: none, level: auto, title: auto)` | Writes a member down for the member checks of SIA 265 4.2 (§3.3undecies): its section, strength class and moisture class — read from the position of the same name where there is one (its `section`, §7), each written over by its argument, `d:` for a round one — and the values they give, in a `var-domain` named after it. Level 1 the position's line, `T001: Träger, Fichte C24, 100/200 mm, Feuchteklasse 1`, with its description (`description: true`) and its axes (`axes:`) — the line `show-position` printed until v0.94, which it replaces for any position —, 2 its section and design values, 3 how each is found. It computes a timber of Tabelle 8 or 9 with a `rec` or `cir` section and a moisture class, and writes anything else down as not calculable, with the reason every `verify-*` then gives. | `#member("S001")`, `#member("T001", level: 1, description: true)`, `#member("R1", d: 200, grade: "GL24h", moisture-class: 1)` |
| `verify-tension`, `verify-compression`, `verify-compression-perp`, `verify-bending`, `verify-bending-normal`, `verify-shear`, `verify-shear-off`, `verify-shear-perp` | `verify-<check>(member, <actions>, level: auto, title: auto, name: auto, unit: auto)` | The eight checks of SIA 265 4.2.1 to 4.2.9 on a member written with `#member` (§3.3undecies): a run of `#eq` and `#verify`, «Tragsicherheit» and «Stabilität» as two parts, the branch of k_c and k_m that holds, and what they work out published in `"<member>-verify-<check>"`. N signed, tension positive; an action is a number, a value with its unit, a registry name or a var object. Level 0 nothing, 1 the verdicts, 2 the stresses and the norm's relation, 3 everything in numbers. ⚠️ `verify-compression` takes **`stability:`** (07.10.2026; true by default): false checks the section alone, σ_c,0,d ⩽ f_c,0,d, with no buckling length, no «Stabilität» part and η the section's — what `#show-check-member` calls along the grain. | `#verify-compression("S001", N: -40, l-k-y: 3000, l-k-z: 3000)`, `#verify-bending("P", M-y: "30 kNm", a: 6000)` |
| `show-check-member`, `ids("check-member")` | `show-check-member(id, level: auto, member-level: 1, description: false, title: auto, unit: auto)`, `ids("check-member")` | **A member check saved in Woodcore, computed in the report** (v0.117, §3.3unvicies): `ids("check-member")` is the data access, every check of `data/checks.json` in file-name order; `show-check-member` reads the check's record — its strength class, section and moisture class resolved by the export, each its position's or the one stated in Woodcore — and calls `#member(id, b:, h:` or `d:, grade:, moisture-class:, position:, impact:, …)` then the check of its kind — `#verify-tension(id, N:, alpha:, …)`; for a compression `#verify-compression(id, N: "-…", stability: false, …)` along the grain and `#verify-compression-perp(id, F:, l:, w:, alpha:, case:, larger:, …)` at an angle — with every value written out, so the page is the one that command prints and nothing the page prints is computed in Python. `level` is the check's (that command's: 0 nothing, the check still made, 1 the verdict, 2 the stress and the relation, 3 how each value is found; auto follows the report); `member-level` the member line's (`#member`'s, 1 by default, `none` no line, the member still written down); `description: true` adds the position's description; `title` the check's heading (auto, none, a string); `unit: "%"` the utilisation in percent. ⚠️ The member's var-domain is the check's id, so what it works out is published in `"<id>-verify-<check>"` (`"<id>-verify-tension"` for a tension). A check the export marked not calculable, an unknown id and a kind not implemented yet (only tension and compression are) are refused naming the reason or the valid ids. | `#show-check-member("ZT-01")`, `#show-check-member("ZT-02", level: 3, member-level: 2, unit: "%")` |
| `show-check-steel`, `ids("check-steel")` | `show-check-steel(id, level: auto, shown: none, title: auto, unit: auto)`, `ids("check-steel")` | **A steel check saved in Woodcore, computed once in Python** (issues #50, #51, docs/domain/steel.md §3.3quatervicies; lib/steel.typ): `ids("check-steel")` is the data access, every check of `data/steel.json` in file-name order; `show-check-steel` prints the rows the export holds — the designation, the grade and the position, then the given values, the steps with their formula and clause, the ratio and the answer — through `show-calc`, evaluating nothing again (D-09). `level` is the check's (0 nothing, the ratio still registered, 1 the verdict, 2 the resistances, 3 how each value is found; auto follows the report), `shown` with `level: -1` the values named; `title` the heading (auto the kind and id, none, a string); `unit: "%"` the utilisation in percent. ⚠️ The ratio is published in `"<id>-verify-steel-<kind>"`, which the summary reads. A check the export marked not calculable prints its reason; an unknown id is refused naming the valid ids. | `#show-check-steel("ST-01")`, `#show-check-steel("ST-02", level: 3, unit: "%")` |
| `moisture-class-of` | `moisture-class-of(position)` | Data access, not display (v0.36): a position's moisture class, `1`, `2` or `3`, or `none` where the Positions Element sheet leaves it blank (§7) — what a calculation written in Typst picks its factors by. Works in a plain `#let`, like `var-of`. An unknown id fails listing the valid ones. | `#let fk = moisture-class-of("T001")` |
| `show-polar-moment` | `show-polar-moment(connection, N: 0, V: 0, M: 0, level: auto, title: auto, width: 60%)` | Distributes N, V (kN) and M (kNm) over a connection saved in Woodcore — drawn on a detail schema, and naming no connector since v0.76 — and prints the force in its fasteners (§3.3quinquies): level 1 the most stressed one(s); level 2 the figure with every fastener's N/n, V/n and resultant drawn to one scale (all at one scale, so that they add up; a share too small to make out is named with its value in the legend's last line), `n = 4; I_p = 28800 mm²` under it, each formula in letters and its own numbers line on one row, and the force-grain angles; level 3 first the positions table, then the rotation centre and how it is found, the reference member and the angles between the members, then level 2's content in full and every fastener in a table (F_x, F_z, β₁ … β_m, F), then again in the most unfavourable superposition (F*_x, F*_z, F*: N, V and the force from M added component by component with their magnitudes, v0.37). Fasteners carrying the same largest force are all named (`Verbindungsmittel 1–4`), the working shown for the first. The reference is cited once, beside the heading. N, V, M take a number or a var (unit checked). The one calculation the engine carries out itself (§13), and since v0.85 it **publishes** what it worked out — F_max, every fastener's resultant, the force-grain angle towards each member — into a var-domain named after the connection, which `#val`, `#var(domain:)` and `#find` reach; its answer line names the largest and which fastener carries it, `F_max = F_1 = …`. An unknown id, a bad level or force, or M on a group with I_p = 0 fails with a message saying what to fix. Named `show-fastener-forces` until v0.32 and `show-fastener-polar-moment` until v0.38. | `#show-polar-moment("SD_02-10mm", N: 7.5, V: 25, M: 6.6)` |
| `show-connector` | `show-connector(connector, description: false, level: auto)` | Displays one connector on a line (§7bis): its type and assembly, `Ø` diameter and `L` length in mm, other dimensions, steel, predrilling, and the elements it joins in parentheses, leaving out what the source leaves empty. `description: true` appends its free text. The connector's counterpart to `show-position`. An unknown id fails listing the valid ones. | `#show-connector("SD001", description: true)` |
| `show-connector-resistance` | `show-connector-resistance(connector, level: auto, title: auto, width: 100%)` | Displays the design value of the shear resistance of one connector, SIA 265 6.2.1 (§3.3nonies). Level 1 names the connection — «4 × Ø 10 mm Stabdübel, C24, Holz-Holz einschnittig» — and gives R_d, R_d,Verb and the connection's K_ser,Verb, with the minimum distances of Tabelle 24 beside them, laid out as the classeur lays them out; level 2 adds the drawing of the members and the fasteners and the section through the joint, side by side, each a figure with its caption (`width` is the pair's); level 3 then delegates the whole chain to `show-calc("connector", id)`, so the detail is the data's own walk and cannot drift from it. The warnings the export carries — a count set by hand, a distance below Tabelle 24 — are printed under it from level 2. An unknown id fails listing the valid ones; one the export could not calculate fails with the reason it carries, which is the same refusal `find-calculation` makes for `show-calc` and `var-of`. | `#show-connector-resistance("SD_02")`, `#show-connector-resistance("SD_02", level: 3)` |
| `show-live-load` | `show-live-load(category, level: auto, title: auto)` | Displays the live load of one category of Nutzfläche, as SIA 261's Tabelle 8 gives it (§3.3septies): level 1 the category with q_k and Q_k on one line, cited beside it; level 2 the same line naming what the category is and carrying the table's notes on it as one footnote; level 3 Tabelle 8 entire above that line, this category's row bold on a tinted ground. `title: auto` prints no heading — the line names its own category — and a string prints one. The wording is the data's: this assembles the labels and values `data/calculations.json` carries. An unknown category fails listing the valid ones; category E, whose values SIA 261 8.2.2 leaves to the project, fails saying so. `show-calc("live-load", category)` renders the same record generically. | `#show-live-load("A1")`, `#show-live-load("H", level: 3)` |
| `show-plan` | `show-plan(plan, width: 100%, legend: true, highlight: none, detail: false, zoom: 1, axes: true, dimensions: true, lengths: true, centres: true, scale-bar: true, caption: auto)` | Displays a position plan drawn in Woodcore (§3.3sexies): the architect's plan faded under the STE symbols, their position numbers and the axes, cropped as saved; under it the scale bar, where the plan has a scale, and the legend, in the report's typeface; and a caption with the printed scale. `highlight` (a number or an array) puts a halo under those positions. `detail: true` shows only their surroundings at the whole plan's scale, and `zoom` enlarges that. `axes: false` leaves the axes out, `dimensions: false` the dimensions, `lengths: false` the lengths beside the elements (issue #9), `centres: false` the stiffness centre S, the mass centre M and the building's outline with their lines of the legend -- which the plan prints only where its own switch says so (issue #54, §3.3sexies) --, `scale-bar: false` the scale bar, and `caption: none` prints the plan without a figure around it. A plan taller than it is wide is kept within three quarters of the page's height. | `show-static-model` | `show-static-model(model, width: 100%, loads: true, dimensions: true, highlight: none, caption: auto)` | Displays a static model drawn in Woodcore (§3.3octies): the members, the supports, the releases and the loads, each load with the name and value its `show` mode asks for, and the influence width b_e where it carries one.
