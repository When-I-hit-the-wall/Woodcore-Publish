# Tests and tool versions

> tests/, how to run them, what each file guards, pinned versions of Python, Typst and packages.
>
> Moved verbatim from CLAUDE.md (§11ter) on 2026-10-07. The § numbers are kept as stable anchors: `docs/README.md` maps every § to its file.

## 11ter. The checks, and the versions of the tools (v0.59)

Two files this project needed and did not have, both of them the same argument as §1bis applied one level down. The reference library versions the *edition of the norm* a value was read from; these version the *tool that reads it* and the *proof that it still reads it correctly*.

### `tests/` — every check the engine is allowed to rely on

Until v0.59 every verification this project claimed was written once, run once and thrown away. `CHANGELOG.md` reports more than six hundred checks across the versions — "328 checks pass across the four suites", "124 assertions", "59 assertions of its own" — and **not one of them was in the repository**. They were therefore unrepeatable: a change to `statics.py` could not be held against the 111 checks that had passed the day before, because those checks no longer existed.

They live in `Woodcore/tests/`, and are run with

```
python tests/run_tests.py
```

**The tests work on an example project (v0.81).** `tests/projet-exemple/` is a real project anonymised — its Woodcore sources, its export, its report — with no workbook, blank pages in place of the architect's plans and a blank of the same size in place of every picture (the engineer's decision, 19.09.2026). `conftest.py` copies it beside `tests/.tmp/` once per process (`tests/.project-<pid>/`, removed at exit), syncs the engine into the copy and makes it the current project, so a test never writes into the committed example and two runs never share one. A probe is compiled in that copy's report folder (`conftest.probe_dir(name)`, `--root conftest.TYPST_ROOT`), and an import into the engine or the export is computed (`conftest.import_path`). The few checks that need a workbook read the engineer's own project, `conftest.real_project()` — `WOODCORE_REAL_PROJECT`, else the one beside the checkout — and skip on a clone without one; the cells of `Verbindung.xlsm` are frozen in `tests/fixtures/verbindung.json`, and a test on the engineer's machine says the workbook still holds them. A full run skipping more than `MAX_SKIPPED` (15) fails: a run in which the suite quietly skipped would otherwise pass while checking nothing.

**No framework.** The runner is about a hundred lines of standard library — the project already carries three dependencies (below), and a fourth whose only job is to call functions whose names begin with `test_` would be one more thing to install before a report can be checked. `pytest`, where it happens to be installed, discovers the same files unchanged: the convention is its own (one file per concern, one function per check, plain `assert`). A test that cannot run here — no workbook, no Typst binary — raises `Skip` and is counted as skipped, never as a failure — by `run_tests.py`, and by pytest as well, `Skip` being a `unittest.SkipTest` (audit 260916).

**Preparing a machine: `python tests/bootstrap.py`** (v0.117, issue #26). A fresh clone ran 1335 tests, skipped 1117 and failed 149 on 10.10.2026 — none of it the code's: nothing installed `requirements.txt`, Linux lacked the libraries Qt opens (libEGL first), and Typst was not there, so every test that compiles skipped. One command now prepares a machine for the whole suite, the standard library only (it runs before anything is installed): the packages `requirements.txt` pins, by one `pip install -r` where one is missing or at another version; on Linux the system libraries Qt needs to draw without a screen (`libegl1`, `libxkbcommon0`, `libgl1`, `libfontconfig1`, `libdbus-1-3`), by `apt-get`; and **the Typst `typst-version.txt` names**, from its official archive on GitHub into `~/.local/bin` (`%LOCALAPPDATA%\Woodcore\bin` on Windows, `--prefix` otherwise), **refused unless its SHA-256 is the one `typst-sha256.json` records** — a hash fetched beside the archive would verify nothing. Each part is installed only where it is missing, so a second call installs nothing and says «already up to date». `--check` says what is missing and installs nothing (exit 1 if anything is); `--typst-only` is what `.github/workflows/site.yml` calls; a new Typst's hashes are recorded by `--record-hashes <version>`, the one step `typst_check.pin` cannot do offline. This file is the only list of what a test machine needs: the CI (`tests.yml`, §12), the site's workflow and the hook `SessionStart` of `.claude/settings.json` — which runs it in Claude Code's cloud sessions only (`CLAUDE_CODE_REMOTE`), never on the engineer's machine — all call it. Prepared so, a clone runs with 0 failures and under the ceiling of skips. **It also writes the engine's copy beside the frozen examples** (`examples/lib/`, `examples/commands.typ`) where it is missing or not today's `lib/`, by `build_examples.refresh_engine` as `packaging/build.py` does: the copy is generated and not versioned, so a clone has none, and `test_commands.py` failed four tests and skipped two on a fresh clone until a later test happened to write it.

**Qt without a screen, set once** (v0.117). `tests/conftest.py` sets `QT_QPA_PLATFORM=offscreen` for every test and every process a test starts, where some seventy tests each set it themselves and a few forgot; a value already set wins (`tests/test_no_console.py` removes it on purpose, for a real window).

**The tests of time are apart** (v0.117). A file that sets `PERF = True` at its top runs with `python tests/run_tests.py --perf` only; left out, it is neither run nor counted as skipped. Only the start screen's 1.5 s is such a test (`tests/test_startup.py`): a slow or shared machine — a CI runner, a cloud session — must not fail the functional suite over a time. What the start loads is functional and stays in every run (`tests/test_startup_imports.py`). The runner's exit code is its contract with a CI job (`run_tests.exit_code`, `tests/test_runner.py`): 1 for a failure, 1 for a full run that skipped more than `MAX_SKIPPED`, 0 otherwise.

**So are the tests of another system** (v0.117). A test of Windows' own behaviour -- a console window that must not flash (`test_no_console.py`), the Windows API the stall watch uses (`test_stallwatch.py`), Windows' fonts (`test_theme.py`), and on Windows or macOS a file system that tells two names apart by their case (`test_connectors.py`) -- raises `conftest.OtherSystem` elsewhere, not `conftest.Skip`: the runner prints it dimmed and counts it apart ("N tests of another operating system left out"), not among the skips `MAX_SKIPPED` (15) bounds, because it says nothing missing from this machine, and the CI's Windows job runs it. Every other skip -- no tinymist, no project of the engineer's, no reference library beside the program -- still counts. pytest sees both as skips.

**Where the time goes** (v0.117). `python tests/run_tests.py --times` prints, after the summary, the seconds of every file — its import included, a module that loads Qt or compiles at import costing there — slowest first with its share of the run, then the ten slowest tests. It combines with `-k` and `-v`; without it the output and the exit code are the same as before. Measure before splitting the suite into fast and slow: the cost is not where it is guessed to be.

**One process per file, a time limit per test, and a rerun of what failed** (v0.117, issues When-I-hit-the-wall/Woodcore#22 and #23). The runner starts every `test_*.py` in a process of its own (`run_tests.py --worker`), as many at once as the machine has cores (`-j N`, `-j 1` for one at a time), the slowest first as the previous run measured them (`tests/.timings.json`, gitignored, one time per test). **A file whose tests took longer than `SHARD_S` (150 s) is cut into parts**, one process each, its tests dealt the longest first to the least loaded part: `test_fire_tab` alone took 24 of a 25-minute run before it was cut. A worker ends by running the `atexit` handlers and `os._exit(0)`, without tearing Qt down: `test_notice_bar` and `test_toolbar` crashed at interpreter exit (0xC0000409) after their last test, which one process for the whole suite had hidden. A process is a whole `conftest` -- its own copy of the example project, temporary directory and settings, all under its pid -- so the files run side by side exactly as two whole runs always could; the output of a file is printed in one block when it ends. **A test running longer than `--test-timeout` (300 s) is stopped**: `faulthandler.dump_traceback_later` writes the stack of every thread first (`-v` prints it), the test fails under its own name with «stopped after 300 s -- stuck», and the tests after it in its file run in a new process. Until then a single test waiting on something that never came -- a modal `exec()`, a `wait()` without a limit -- held the run all night with nothing said: the engineer left a run going for more than seven hours, and the one sequential process had reached `test_views` at 07:08 having started at 00:07. The first run with the limit named the main culprit: `test_editor.test_the_language_server_survives_every_file_of_the_report` started one tinymist per file of the example, **181 of them**, with 2.3 s of handshake each and up to 60 s per request -- hours on a busy machine. It now opens every file in one server, as VS Code does, and takes 25 s; a server still dies on the file that kills it, which the test names. What failed is kept in `tests/.last-run.json` (gitignored): `--failed` reruns those tests alone, and `--related <file>…` reruns the test files whose text names one of the modules given (`calc/renumbering.py` → every file mentioning `renumbering`) together with the previous run's failures -- the repair loop of the `finish` skill (`.claude/skills/finish/SKILL.md`): the full suite once, then only what failed and what the repair touched, until green. The budget of a full run is **20 minutes**: 25 min 18 s with one process per file, 13 min 23 s once the long files were cut, 9 min 38 s once every test had its own time (8 cores, 2 650 tests, 10.10.2026), against more than seven hours in one process.

⚠️ **`tests/projet-exemple/Formules` carries Windows' read-only attribute** and `copytree` copies it, so `conftest._wipe` was refused the folder at every exit and each run left its `tests/.project-<pid>` behind -- forty after one night, which `test_harness`'s walk of every `.py` under `tests/` then went through, and which vanished under it when a parallel run ended. `_wipe` now clears the attribute on a directory it is refused (`_rmdir`), and the walk passes over every directory of `tests/` whose name starts with a dot.

**A test builds its own workbook.** `tests/fixtures/workbook.py` writes a minimal Belastungsannahmen sheet with only what the reader reads. A test pointing at `Belastungsannahmen.xlsm` would fail the day a row is edited, and a test that fails for a reason nobody caused gets deleted rather than fixed — and a defect has to be *put into* a sheet to check that the export refuses it, which nothing here may do to the engineer's files. The tests that read the real workbooks — `test_dead_load.test_the_engineers_own_workbooks_still_pass`, `test_norms.test_grades_match_the_workbook` (`Verbindung.xlsm`) and `test_export.test_the_export_is_reproducible`, which runs the whole export — only read them, and are skipped where they are not there.

**One temporary directory per process** (v0.64.2). A test that writes -- a `.typ` to compile, a workbook to read back -- asks `conftest.tmpdir(name)` for a directory, and that directory now sits under the **process id**: `tests/.tmp/<pid>/<name>`. Until v0.64.2 it did not, and `tmpdir` wipes and recreates what it is handed, so two runs of the suite at once removed each other's files in the middle of a test. What came out was `file not found (searched at ...\tests\.tmp\formula\probe.typ)` -- a message that cannot come from the code under test, and that reads exactly like a defect in it.

It cost two sessions a day between them to name, which is why it is written down here rather than only in the changelog. **20, 21 and 29 failures in a shared run against 0 for the same tests run alone**, measured independently on both sides; every failure in a suite that writes a `.typ` and none in the nine that do not; and a duration that says nothing either way, a run that aborts early being short and a warm run shorter still. `conftest.cleanup()` removes this process's directory and takes the parent with it **only when it is empty** -- not empty meaning a neighbour is still running, where refusing is the right answer -- and it is registered with `atexit`, which is what covers pytest, since pytest never runs `run_tests.py`. The removing lives in `conftest` alone: the runner carried a second copy of the loop, and a second copy is what let the repair be applied to one of them and not the other.

⚠️ **The per-pid path is one directory deeper, and a probe's `#import` must not care.** Typst resolves a relative import from the importing file, so a literal `"../.."` in a probe would have broken the moment the repair was applied -- with the very message the repair exists to remove. Every import a test writes is therefore absolute (`"/commands.typ"`, read from the Typst root) or built from a prefix computed at run time, and `test_harness.py` is what keeps saying so. ⚠️ Two hazards it does **not** cover, both in `test_export.py` and both outside `tests/.tmp` altogether: the ghost record it plants in `data/positions/`, and `test_the_export_is_reproducible`, which reruns the real export into `data/` -- shared state no per-process path can separate.

**What each test file guards** is in two catalogues beside this file, one row a file (moved there on 2026-10-10, issue #31): [`testing-catalogue.md`](testing-catalogue.md) — the engine, the norms, the documents, the build — and [`testing-catalogue-window.md`](testing-catalogue-window.md) — the window and its tabs, built off-screen. A new test file takes a row in one of them; `tests/test_docs_coherence.py` refuses a `tests/test_*.py` that has none.

👉 A check that caught a real defect keeps that defect in its docstring, with the version it was found in. That is what tells the next reader whether the check is still earning its place, and it is why `test_dead_load` names `EL+AL-Dach ohne Wasser` and `test_export` names `D001`.

### `requirements.txt` — the three packages, pinned

`openpyxl`, `pypdf` and `PySide6`, at the versions this report was built against. Pinned exactly rather than given as a floor, for the reason §1bis gives about norm editions: a report built in 2026 and checked in 2031 is rebuilt with the openpyxl that read the workbook, not with whatever is current then. Typst is not in the file — it is a binary, not a Python package — and its version is named in a comment there.

**Woodcore checks the machine against that file** (`calc/tools/dependencies.py`, §10quater). Two questions, kept apart because they cost different things. *Is what the project asks for installed?* is read out of the running interpreter: instant, offline, and a mismatch is worth interrupting for, since a workbook read by another openpyxl is not the workbook this version was verified against. *Is there anything newer?* is a request to PyPI: it runs in a thread of its own, says nothing when it fails, and only ever offers — a banner with a button, never a modal. Installing a newer version also **pins it**, in the same action: installing without pinning would leave the file stating one version and the machine carrying another, which is the disagreement the first question reports, arrived at from the other side. Nothing installs without a yes.

### Typst and Python — the two versions pip does not pin

`requirements.txt` pins the three packages; the two tools underneath it are named elsewhere, and both are checked rather than assumed.

| | version | where it is named | what checks it |
|---|---|---|---|
| **Typst** | **0.15.1** | **`typst-version.txt`** alone (v0.117, issue #26), the SHA-256 of each official archive in `typst-sha256.json`; `packaging/build.py`, `packaging/notices.py`, `tests/bootstrap.py` and the workflows read it, and `typst_check.pin` rewrites it (§10quater). Until v0.117 the number was written three times — `requirements.txt`'s comment, `site.yml`'s and `build.py`'s `TYPST_VERSION` — and held equal by `pin` rewriting all three | Woodcore at every start from the sources, `packaging/build.py` before it builds, `tests/bootstrap.py` before it installs (an archive whose SHA-256 is not the recorded one is refused), and `tests/test_typst_check.py` (the number written nowhere else) and `tests/test_bootstrap.py` (a hash recorded for every archive of the pinned version) |
| **Python** | **3.13** (3.13.7 here) | `packaging/notices.PYTHON`, the runtime the third-party notices name, and `.github/workflows/site.yml`'s `python-version: "3.13"` | `packaging/build.py`, which refuses to build on another **minor** version; a patch release is free, so 3.13.7 needs nothing said |
| the packages | openpyxl 3.1.5, pypdf 6.19.0, PySide6 6.11.2 — and PyInstaller 6.22.3 for the build alone (`packaging/requirements-build.txt`) | `requirements.txt` | Woodcore at every start (above) |

An installed Woodcore asks none of it: it carries its own `typst.exe` and its packages are frozen inside it (§12).

**What the move from Typst 0.14.2 to 0.15.1 changed** (checked 27.09.2026, the pin having followed a winget upgrade the way §10quater says it does). Everything compiles — the report in three languages at three uniform levels, and all 276 frozen examples — and the engine's own measurements hold, `tests/test_display.py` included, which reads the stacked `=` signs out of a compiled PDF to 0.2 pt. Four things nevertheless moved, and one of them is red today.

⚠️ **`#verify`'s ✔ and ✘ sit on their line now**, where they hung below it beside the double rule: 0.15 «retains baseline information in many more parts of the layout engine», boxes among them, and the mark is a box beside the double-ruled one. It is a repair and not a regression — the double rule still clears the denominator of a display fraction, which is what v0.88 measured it to — and it is what makes **35 of the 276 pages about 2 pt taller**, every one of them a page carrying a verdict. The 276 were re-rendered on 27.09.2026 (`python calc/tools/build_examples.py`, without `--freeze`, the snapshot not being what moved): all 276 render, the sources and the manifest do not move, and every page differs, the rasterisation having changed with the font bundle.

⚠️ **`panic` prints a string as it is and no longer its `repr`**, so a test that reads a refusal off stderr no longer isolates the message: five regexes across four test files went stale, of which `test_timber` and `test_command_review` **fail today**, the other three passing for the wrong reason — they fall back to the whole stderr, which echoes the engine's source and so still holds the words a substring check looks for. The repair is **`tests/conftest.py`'s `panic_message`**, which reads either form and gives the message alone, `None` where the stderr holds no panic, a compile error being another thing: the five call sites read through it, and the regex is not to be written again by hand (§11ter's table above, `tests/test_timber.py`, `test_command_review.py`, `test_distance.py`, `test_formula.py`).

⚠️ **The SVG lost its `typst-*` classes and the whitespace between its tags**, output being minified by default (`--pretty` gives the old shape). Two of `website/build.py`'s `minify_svg` steps are therefore no-ops, and harmlessly so: the rounding, the path compaction, the short glyph ids and `xlink:href` → `href` still do the work, and `xlink:href` is still what Typst writes. `tests/test_site.py` feeds the minifier a string of its own carrying the old shape, so it goes on passing and no longer says anything about what Typst now writes.

⚠️ **Every other page differs in its rasterisation alone**: 0.15.1 carries New Computer Modern 8.1.1, and `config.typ` names no font, so the report's text and its math are both Typst's own. A table read side by side is identical to the eye.

⚠️ **The pin moving asked two things of the repository itself**, and both were red until they were done. `legal/THIRD-PARTY-NOTICES.txt` names the Typst the installer carries, so it goes stale the moment the pin moves and `packaging/build.py` refuses to build on a stale one (§12): `python packaging/notices.py` rewrites it — three lines here, the fonts carrying no version of their own, so New Computer Modern 8.1.1 asked for nothing. And `tests/test_typst_check.py` wrote the literal `0.15.1` into its copies of the three pinned files, which is what the repository now pins: `pin()` rewrites only what differs, so it wrote nothing and gave back `[]`. It writes `NOT_THE_PIN` now, a version the repository will never carry, and asserts at the top of the test that it is not the pin — so the next move cannot make it pin what is already pinned.

👉 What the 0.15 changelog breaks and this engine does not do, each checked against `lib/`: `lr`'s `size`, a `slice` given both an end and a count, `str`'s `base` on something that is not an integer, the scoped `json.decode` and its kin, the `path` element and the `pattern` type, `cal`, and a backslash in a path. The one that does reach it is **`class()` applying to its direct body alone**, which `formula.typ`'s `atom-symbol` wraps a symbol of several atoms in so that `M2 / a` is a fraction of M2 (§10quinquies); its examples compile and read as they did.
