# The «Structure du document» tab

> *Structure du document*: moved verbatim from [`window.md`](window.md) (§10quater) on 2026-10-10 (issue #31), the file having reached 218 KB. `window.md` keeps the window's frame and the index of the tabs; a reference to `docs/ui/window.md §10quater` finds this file there.

## 10quater (suite) — «Structure du document» tab

**The «Structure du document» tab (v0.112).** *Structure du document / Dokumentstruktur / Document structure* (`calc/tools/structure_tab.py`, its words under `st_` in `structure_words.py`; the **first group of the navigation**, *Document*, `("nav_document_group", ("tab_structure",))`, above *Projet*) is **the one tab a document is written in, in the convention d'utilisation, the base de projet and the report alike** — the engineer's rework of 01.10.2026, which replaced the two tabs of the first build, a structure tab and a «Sections» tab with a coloured Typst code editor of its own (`sections_tab.py` is deleted, its words and its icon with it). ⚠️ **No Typst code is ever shown in it**: it has no code editor and no highlighter, which `tests/test_structure_tab.py` holds, and the engineer who wants to read or write code opens the file in VS Code; the tab **follows what he writes there** — it watches the document's `Sections/` folder, its entry file and its `structure.json` (`QFileSystemWatcher`, **while the tab is shown**: a watch holds a directory on Windows) and reads the tree again, debounced, when what is on disk is not what it last read, the pane of the object chosen included; the files it wrote itself are not read again. It has no `dirty`: it writes at once, and it is one of `MODE_BOUND`, so that an edit pending in a pane is written before another document is shown (`confirm_leave`). **Nothing is computed or compiled before the tab is shown**: the window builds every tab when it opens, and a preview is a compile, so the pane is given its document the first time the tab is shown (`showEvent`).

**At the left, the tree** (`calc/tools/structure_tree.py`, which shows what `structure.tree` gives and reads and writes no file): **chapters › sections › objects**, a row an icon for what it is (a chapter, a section, and each kind of object), a `.typ` mark where the node is a file of its own (the report's alone: in a convention and a base every section is a file, and the mark and its legend are left out there), a link mark where that file is shared with another document, and a **sync mark** where what is shared changed in another document; a box on every chapter and section, ticked while it is printed — a disabled chapter switches off everything under it —, and none on an object, whose file's state is its own; a row not printed is greyed, its box keeping its own state, and one whose file has something wrong with it is in the warning colour with its tooltip saying what. Above it, «1 · 2 · 3 · Tout» open the tree to a level, and the buttons: **+ Section…**, **+ Chapitre…**, **+ Objet** (a menu of the kinds an object can be), **Retirer** (a section is archived into `Sections/archives/`, an object copied there first, neither deleted), **Id…** (renames a section, and so its file; refused where it is shared), **Importer…**, **Baliser ce fichier** and **Enregistrer comme modèle…**; where the document shares anything with another, the three of the **synchronisation** — **Importer les modifications**, **Ignorer**, **Réactiver** — and a line counting what is to import, in conflict and ignored. **Selection** is extended, Ctrl and Shift as an explorer has it. **Drag and drop** is Qt's gesture and never Qt's own move: a drop says what was dragged, where it was dropped and `above`, `below`, `on` or `end`, and the tab asks the model to move it (`structure.move_node`, `doc_import.move_object`) and reads the tree again from what the files then say — a section or a chapter anywhere in the tree, an object within its file or into another file, above or below another object; sections and objects are not moved together, an object is not put into a chapter, and a heading of a file that carries no tags is not moved alone (a refusal says which, and «Baliser ce fichier» is the way out).

**In the middle, the page of what is chosen and nothing else** (`calc/tools/pdf_pane.py`, `PdfPane`; the page is `calc/structure_preview.py`'s, §3.3octodecies): a small source compiled from standard input, `request_snippet`, in about half a second — one compile at a time and only the latest request, a snippet asked for while the document's own compile runs ending that compile —, shown in a `QPdfView` over a `QPdfDocument` **loaded from a buffer** and never opened as a file, because a Windows handle on the PDF would make the next compile, which writes that file, fail on a sharing error. «Compiler l'aperçu» compiles the **whole** document in the background into Woodcore's cache (`usersettings.cache_dir("preview")`, never over the deliverable, with `stamps.deps_file(..., preview=True)`) and the banner says «Modifications non compilées» where what is shown is not what the sources would give (`stamps.changed(..., preview=True)`); where a compile fails, Typst's own message stands in a banner and never in a modal — a section half typed does not compile —, and what was shown stays shown. The tab says it in the preview's title: «Aperçu : le document entier», «Aperçu : « Nutzlasten »», «3 éléments choisis».

**At the right, the options of what is chosen** (`calc/tools/object_panes.py`; **no Typst code**): `ObjectPaneHost` swaps the pane as the selection moves, shows a sentence in its place for nothing or for several rows, and flushes what the previous pane had pending **first**, before it changes what it considers current. A pane is a column of cards over one model of `calc/typst_objects.py` (or over a body string, or a small state) and speaks three things: `load(subject, context)`, which shows and says nothing, `changed(payload)`, emitted after an edit with a **snapshot of what the pane now holds** — a button at once, typing after a 400 ms debounce so that a paragraph typed is one write and not forty —, and `flush()`. The panes: **a table** (`doc-table`, `dead-load-table`: the list of its rows with add, remove, up and down, the fields of the row chosen, one for each column printed, the list of its columns with a box each — printed or hidden, hidden columns **kept** —, the title of the one chosen, a caption, the notes); **the live loads** (as the table, and per row a drop-down of the categories of SIA 261 Tabelle 8 named in the window's language, `q_k` and `Q_k` in fields that show the export's value and take the engineer's own, **orange with «Reprendre»** the moment one is written over — b/h's rule of v0.75); **a choice** and **a list to tick** (the label, the options with add, remove, up and down, and the paragraph of the one chosen); **the signatures** (the signatories and the five fields of the one chosen); **the norms** (a check list of the catalogue's documents, by designation and title in the window's language, and of the project's own `references.bib`, with the free lines of the engineer's own under it); **a field**, **a picture** (its file chosen under the project's folder), **a plan extract** (the plan, the positions on a halo, the close-up, the axes, the legend, the scale bar, the width and the caption); **a heading** (its text and its level) and **a paragraph** (a plain text box holding its markup as written, checked as it is typed: a blank line, a heading line or an unclosed bracket is said in a sentence and the body stays the last that was valid); and **a section** (its title, its file, whether it is printed, **its sharing** — a card «Partage» naming the documents it is shared with, with «Partager avec…» and «Arrêter le partage», below —, and «Baliser ce fichier» where it holds text that is not tagged yet) and **a chapter** (its title in each of the three languages, the document's own being the one printed, and whether it is printed). A variable put in a cell is chosen in a picker fed by the compiled report's variables and the export's, filtered by every word in any order, and **shown as the variable** (`g_k = 1.9 kN/m²`) and never as the call that writes it. A refusal of a model is said in a banner of the pane, in the window's words and never in a modal — the engineer is typing — and the model is left as it was; an object written in a form Woodcore cannot edit (an argument that is an expression) says so and offers no editor; and **no ψ is ever shown**. After a pane has written its edit the tab does **not** load the same object back, which would lose its selection.

**What writes, and how a refusal is said.** Every write goes through the module that owns it — a section's state, title and place through `calc/structure.py`; an object's body through `calc/typst_objects.py`, **only the bytes between its two tags changing**; an object's place and what is imported through `calc/doc_import.py`; what is shared through `calc/sync.py` — and the tab says a refusal in the window's own words, **one `st_why_<code>` for each code of the five modules** (`structure_words.CODES`, held equal to their union by a test, a few in two forms where the same code means two things), in a banner over the tree and never in a modal. An object **written by hand** in a form Woodcore does not write asks first, naming what will change (the diff) and then rewrites it; **a file changed under a pane since the pane loaded refuses the write** (`changed`) and the object is read again, what was being typed not being written. A project held read-only (project_lock.py) writes nothing — the guard is `WRITERS`, wrapped once on the class — and keeps its forms readable. «Enregistrer comme modèle…» writes nothing into the project, and is open to one held read-only.

**What is shared shows where it stands.** The tree and the buttons follow one `sync.Status` (`apply_sync_status`): a file or object whose copy in another document changed since this document last synchronised is **orange** (`incoming`), one both changed **red** (`conflict`), one the engineer chose to ignore **grey** (`ignored`), one whose copy cannot be compared in the warning colour (`problem`), and `local` — only this copy changed — gets no colour, being no alarm; **the mark column says it in a character as well**, a colour never being all there is. «Importer les modifications» takes the other version between the tags — all of what is incoming, or the selection's — and asks, for every conflict, which version to keep: this document's, the newest, or a named document's (`ask_choice`, a dialog of choices; the text of each document's version stays in the status for a diff); «Ignorer» and «Réactiver» set and take off the flag, **per document and until it is taken off**. The tab's own edit of an object inside a shared block writes **this document's copy alone** and tells calc/sync.py (`sync.record_local_edit`, through the tab's `record_edit`): the other documents show it as incoming, and where the record cannot be written the object is written all the same and the status line says so. A change on disk — VS Code — is the same: the tab reads it and the state follows, with no further word to say.

**The dialogs** (`calc/tools/import_dialog.py`, each answered by a method the tests replace, a modal off-screen never coming back): a new section or chapter (the title and the id, the id **following the title** — `structure.suggest_id` — until it has been typed into, the chapter given its title in the three languages); **«Importer depuis un autre document»** (a combo box of the other documents, the tree of its chapters, sections and objects made again whenever another is chosen, a box on every row — a chapter ticks everything under it, a section its objects, and **a section ticked whole is imported whole** where one with only some of its objects ticked imports those objects alone — and «Copie indépendante», unticked: what is imported stays linked); **«Partager avec…»** (`ShareDialog`: the project's other documents, one the section is shared with already shown ticked and closed with its reason, and where only one can be chosen it is ticked; `sharing.share` then makes the copies, and «Arrêter le partage», asked first, is `sharing.stop_sharing`: the file then shows a **greyed link mark** in the tree for as long as the tab is open, the tags being gone from the file and the files keeping no memory of it); **«Enregistrer comme modèle…»** (the name in the document's language, the description, and the place: the engineer's own templates or the office's shared folder, the choice closed with its reason where the settings name none; an existing template asked about before it is written over, and what is worth knowing about the template — a file it names and does not carry, a file whose tags Woodcore cannot read — said in a box afterwards).

**Document templates and styles outside the tab.** *Fichier → Paramètres…* gained a sixth page, **Modèles de document**, beside *Modèles* (which are the templates of a whole project): the document templates of the three places, one row each — the document, the template's name in the window's language, the languages it exists in, its place — with **Supprimer** (the template is moved into its place's `archives/`, never deleted; a builtin one is read only, the button closed with its reason as its tooltip) and **Ouvrir le dossier**; `doc_error_text` writes a refusal in the window's language by its code. **«Nouveau projet»** gained, for each of the two documents, a drop-down of the templates that exist **in the project's language** (`doc_templates.list_templates(mode, language)`, «(aucun modèle dans cette langue)» where there is none), a project template that already carries its documents saying so and copying them as they are, and a **Style** drop-down; the three folders, the language and the people are as in v0.111. **The project's properties** (*Fichier → Propriétés du projet*) gained the same **Style** drop-down, which replaces the project's `config.typ` after asking — «(config.typ modifié à la main)» standing in the list when it is no style's — and keeps the document's language (`templates.replace_config`); `on_properties_changed` tells the structure tab, whose preview is then compiled again.

**Since v0.122** (issues #87, #90): the tab is the second row of the navigation, under «Projet» (`docs/ui/tab-project.md`), which the window opens on and every change of document brings forward; hidden, the tab compiles nothing at a change of document -- its page is given its document again as it is shown (`StructureTab.on_mode`, `showEvent`) --, and a document not made yet is neither shown nor compiled. «Changer de template de fond…» is retired, a document's content template being chosen once, as it is made; «Enregistrer comme template de fond…» stays.
