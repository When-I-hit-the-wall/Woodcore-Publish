# Recommandations 1 à 8 de l'audit du 10.10.2026 — Spécification

## 1. Objectif

L'audit du 10.10.2026 (issue #25) a produit neuf recommandations, acceptées par l'ingénieur. Il demande d'en implémenter huit (#26 à #33). La neuvième (#34, les normes SIA) attend les PDF qu'il fournira. Dans l'ordre : un environnement de test reproductible et une CI qui servent de filet ; des erreurs qui ne se taisent plus ; les couleurs dans `theme.json` ; des modules et une documentation à une taille qu'on peut relire ; la correction du défaut des unités entre guillemets de `lib/formula.typ` ; le partage des sections dans `woodcore-cli`, avec le schéma de `sync.json`.

## 2. Source

## 3. Exigences fonctionnelles

### #26 — Environnement de test

#### REQ-26-01 — Bootstrap en une commande
- **Exigence** : Woodcore doit fournir une commande unique qui installe `requirements.txt` et le binaire officiel de Typst à la version épinglée (somme de contrôle SHA-256 vérifiée), puis vérifie les versions installées. Elle est idempotente : un second appel n'installe rien.
- **Source** : T26.1, T26.7 — **Priorité** : doit
- **Critère d'acceptation** : sur ce conteneur Linux, la commande appelée deux fois installe la première fois, et ne télécharge ni n'installe rien la seconde (sortie « déjà à jour ») ; `typst --version` donne la version épinglée.

#### REQ-26-02 — Une seule source pour la version de Typst
- **Exigence** : la version de Typst est lue dans un seul fichier, par le bootstrap, par `packaging/build.py`, par `site.yml` et par la CI.
- **Source** : T26.7 — **Priorité** : doit
- **Critère d'acceptation** : `0.15.1` n'est plus écrit à la main que dans ce fichier (et dans les textes historiques ou légaux) ; un test le vérifie.

#### REQ-26-03 — Qt sans écran
- **Exigence** : les tests Qt tournent sans écran, avec `QT_QPA_PLATFORM=offscreen` réglé une fois par le lanceur ou par `tests/conftest.py`, sauf si l'environnement le fixe déjà.
- **Source** : T26.2 — **Priorité** : doit
- **Critère d'acceptation** : sans `DISPLAY`, la suite Qt passe.

#### REQ-26-04 — Les tests de temps à part
- **Exigence** : les tests de temps (`test_startup`, `perf_startup.py`) sont exclus par défaut et ne tournent qu'avec `--perf` (forme : Q-001).
- **Source** : T26.3 — **Priorité** : doit
- **Critère d'acceptation** : `run_tests.py` sans option ne les lance pas et ne les compte pas comme ignorés ; `--perf` les lance.

#### REQ-26-05 — Hook SessionStart
- **Exigence** : `.claude/settings.json` déclare un hook `SessionStart` qui appelle le bootstrap, dans les sessions cloud seulement.
- **Source** : T26.4 — **Priorité** : doit
- **Critère d'acceptation** : le hook est déclaré, et il ne fait rien sur le poste Windows de l'ingénieur (garde sur la variable d'environnement de la session distante).

#### REQ-26-06 — Un clone frais passe
- **Exigence** : après le bootstrap, `python tests/run_tests.py` sur un clone frais Linux donne 0 échec et au plus 15 tests ignorés, hors tests de temps.
- **Source** : T26.5, T26.7 — **Priorité** : doit
- **Critère d'acceptation** : la sortie du run, recopiée en §15.

### #27 — CI

#### REQ-27-01 — Workflow de tests
- **Exigence** : `.github/workflows/tests.yml` se déclenche sur `push` et `pull_request`, appelle le bootstrap (aucune liste de paquets recopiée) puis `python tests/run_tests.py --times`. Il échoue quand le lanceur sort avec un code non nul, y compris quand trop de tests sont ignorés.
- **Source** : T27.1, T27.3 — **Priorité** : doit
- **Critère d'acceptation** : le YAML est valide ; le code de sortie de `run_tests.py` est non nul quand `skipped > MAX_SKIPPED` (test) ; un test cassé fait sortir le lanceur en échec.

#### REQ-27-02 — Plateformes
- **Exigence** : un job Linux à chaque push et PR ; un job Windows sur `main` seulement (Q-001).
- **Source** : T27.2 — **Priorité** : doit

#### REQ-27-03 — Tests de temps, artefact, cache
- **Exigence** : les tests de temps ne tournent pas en CI ; la sortie `--times` est conservée en artefact ; pip et le binaire Typst sont mis en cache.
- **Source** : T27.4, T27.5, T27.6 — **Priorité** : doit
- **Critère d'acceptation** : le YAML contient `actions/upload-artifact`, `actions/cache` (ou `setup-python` avec `cache: pip`) et une clé de cache pour Typst qui dépend du fichier de version.

#### REQ-27-04 — `site.yml` inchangé dans son comportement
- **Exigence** : `site.yml` ne change que pour lire la version de Typst à sa source unique (REQ-26-02).
- **Source** : T27.8 — **Priorité** : doit

### #28 — Exceptions

#### REQ-28-01 — Les 87 cas classés
- **Exigence** : chaque `except Exception` de `calc/` est classé (a)/(b)/(c)/(d) dans l'annexe A de cette spec, et traité selon sa classe.
- **Source** : T28.1, T28.2 — **Priorité** : doit
- **Critère d'acceptation** : l'annexe A contient une ligne par cas avec fichier:ligne, classe, traitement ; plus aucun `except Exception` silencieux non justifié.

#### REQ-28-02 — Un fichier malformé arrête l'export en nommant le fichier et le champ
- **Exigence** : chaque cas (a) lève une erreur qui nomme le fichier et le champ (ou la position) en défaut, et l'export s'arrête.
- **Source** : T28.1, T28.6 — **Priorité** : doit
- **Critère d'acceptation** : un test par cas (a), qui écrit un fichier malformé et vérifie le message.

#### REQ-28-03 — Une donnée manquante avertit
- **Exigence** : chaque cas (b) émet un avertissement avec la raison, visible dans le rapport ou dans la fenêtre (barre de notices, Q-001).
- **Source** : T28.1, T28.3 — **Priorité** : doit
- **Critère d'acceptation** : un test par cas (b).

#### REQ-28-04 — Garde contre les exceptions silencieuses
- **Exigence** : un test refuse tout `except Exception` (ou `except:` nu) dans `calc/` dont le corps commence par `pass`, `continue` ou `return None` sans `# broad: <raison>` sur la ligne de l'`except`.
- **Source** : T28.4 — **Priorité** : doit
- **Critère d'acceptation** : le test passe, et il échoue sur un fichier de démonstration qui enfreint la règle.

### #29 — Couleurs

#### REQ-29-01 — Inventaire et migration
- **Exigence** : chaque littéral `#rrggbb` de `calc/tools/*.py` hors `theme.py` est classé (UI → `theme.json` ; figure exportée → style de figure ; reconnaissance → liste blanche avec commentaire). Les couleurs de l'UI sont lues de `theme.json` sous des clés de rôle (`canvas.selection`…), avec une valeur pour chaque thème que `theme.json` déclare.
- **Source** : T29.1, T29.2, T29.3 — **Priorité** : doit
- **Critère d'acceptation** : l'annexe B donne une ligne par littéral ; la couleur résolue de chaque clé est identique à l'ancienne valeur codée en dur (test), donc aucune couleur visible ne change.

#### REQ-29-02 — Garde des couleurs
- **Exigence** : un test refuse tout littéral `#rrggbb` / `#rgb` / `QColor("#…")` dans `calc/tools/*.py` hors `theme.py` et une liste blanche explicite, dont chaque entrée porte sa raison.
- **Source** : T29.4 — **Priorité** : doit

### #30 — Découpage

#### REQ-30-01 — Règle de taille et garde
- **Exigence** : `docs/architecture/layout.md` §11 fixe une taille cible et un plafond (Q-001 : 1000 / 1500 lignes) et ce qui justifie un dépassement ; un test refuse tout module Python de `calc/` au-dessus du plafond, sauf ceux de la liste d'exceptions de `layout.md`, chacune justifiée.
- **Source** : T30.1, T30.7 — **Priorité** : doit

#### REQ-30-02 — Découpage sans changement de comportement

- **Source** : T30.2, T30.4, T30.5, T30.7 — **Priorité** : doit
- **Critère d'acceptation** : suite verte ; export de `tests/projet-exemple/` (`data/*.json` et PDF) identique avant et après.

#### REQ-30-03 — Aucun calcul dans un onglet
- **Exigence** : un calcul trouvé dans un onglet pendant le découpage est déplacé dans `calc/domains/`, et noté au journal (§16).
- **Source** : T30.3 — **Priorité** : doit
